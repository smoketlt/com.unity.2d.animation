# Uniskin Sprite Mask and Clipping Mask

## Two independent workflows

**Uniskin Sprite Mask** (`UniskinSpriteMask`) is the existing texture-based component, renamed from `UniskinMask`. It reads a separate Sprite's alpha on the target's existing UV surface. The mask follows every deformation of that surface. It adds no contour mesh or separate skinning. The shader name remains `Uniskin/UniskinMask`; its shared lit/unlit materials remain runtime Resources. The previous component's scene settings were not required as a migration contract.

Assign **Mask** to a Sprite outside or inside the PSB. The initial mapping fits both complete Sprite images, respecting their rectangles, pivots, PPU and atlas UVs. Optional **Placement Source** plus **Capture Placement** captures another renderer's placement once. Offset, Scale, Rotation, Invert and Alpha Cutoff change the mapping. **Fit Mask to Sprite** restores the fitted mapping. A generated UniskinRig Sprite uses the imported source image as its affine UV reference, keeping mesh-specific binding changes from moving the mask independently of the texture.

The component preserves unrelated MaterialPropertyBlock entries, uses shared materials, and restores the previous renderer material/mask interaction when disabled or when Mask is cleared. A SpriteMask on Placement Source is temporarily disabled and restored. UV reconstruction happens on changes, Sprite swaps, rig revisions or atlas registration, not on unchanged animation frames.

**Uniskin Clipping Mask** (`UniskinClippingMask`) has a separate contour with its own bone influences and vertex weights. The target mesh retains its independent weights. This supports a body bound to `Spine_1`, `Spine_2`, and `Body_3D`, clipped by a contour bound only to `Spine_1` and `Spine_2`: moving Body_3D slides/deforms the image inside the contour; the two spine bones deform both meshes. The contour is polygon geometry, not a sampled alpha image.

## Clipping authoring

1. Add **Uniskin Clipping Mask** to the target SpriteRenderer layer. Adding it leaves the body image, mesh, weights, material and sorting unchanged. The target must belong to an enabled UniskinRig character and must not already own a SortingGroup or contain other Sprite layers when creating the contour.
2. Click **Draw Contour**. The owning skeleton resolves automatically from the body. The editor creates an empty polygon document and opens **Edit Clipping Mask** directly in New point-authoring mode. There are no Character, Image, Source or contour-asset fields in the ordinary Inspector.
3. Click to place ordered contour points and click the first point to close the polygon. Modify/Create/Delete, symmetry and triangulation reuse the existing Scene geometry tools. Close the popup to save. Fewer than three points cancel back to the empty contour; the body remains unchanged.
4. Once a polygon exists, **Edit Contour** reopens its points and **Edit Weights** becomes available. Both buttons use the ordinary SpriteRenderer Mesh/Weights icons and Inspector styling. The component Inspector contains only these actions, without a vertex-count label; ordering is controlled only through the body's SpriteRenderer. The component uses the supplied `ClippingMask.png` script icon. Authoring helpers and their SortingGroup are hidden from the ordinary Hierarchy/Inspector.
5. In **Edit Weights**, enter **Bind** and pick the desired existing character bones. Only these influences are saved for the contour. Bind initializes missing weights; **Auto** distributes weights across the bound bones, and Direct/brush editing refines them. First Bind exit captures a mesh-specific reference pose through the existing Update Bindings mechanism.

Contour authoring displays the actual body beneath vector points/edges. **Masked** previews the body clipped by the current staged polygon; unchecked, it suspends clipping and shows the full body. The toggle defaults off, shares the other options' row and does not save geometry. Preview uses a transient, unskinned stencil Sprite built from the edited source/deformed vertices and the normal runtime write/body/clear sequence. It never replaces the saved contour Sprite or its bindings. Open New hulls and meshes without triangles show the full body until a closed polygon exists. Turning Masked off or closing/discarding the window removes preview helpers; closing resumes the regular saved mask.

The contour editor does not draw another textured body, source-image bounds, alpha Trace controls or On Top/Dim/Isolate image controls. Weight overlays use a white texture to display polygon weights independently of body image alpha; turning Overlay off does not draw a duplicate body image. A complete polygon activates clipping on save; an empty contour has no rendering helpers or skinning cost.

After closing the initial hull, **Create** inserts points into the nearest polygon boundary edge, including clicks slightly inside/outside it. It replaces that edge with two connected edges and interpolates endpoint weights, then retriangulates. This is clipping-specific behavior; ordinary Sprite mesh Create still supports interior vertices. Deformed authoring maps the click back to source coordinates before insertion; Symmetry inserts the mirrored boundary point too. The former unstyled instruction label below the window body was removed because it overlapped the vertex counter.

Clipping contours open a separate `SceneEditClippingMaskWindow` using `SceneEditClippingMaskWindow.uxml`. Its two button rows contain Modify/Create/Delete and New/Reset; Symmetry/Deformed/Triangles/Masked share one row. Copy, Paste, Generate, Trace and image-only toggles are absent from this template. It shares the tested geometry session, save/lifetime behavior and common window styling with Edit Mesh; the ordinary Edit Mesh template is unchanged. The focused window test checks its concrete type, missing commands and common toggle parent alongside point-authoring entry/cancel.

Removing a component can leave its saved, disabled authoring child in the scene. On a subsequent Draw Contour, Create recognizes orphaned direct children by the hidden `Uniskin Clipping Contour` name and their ClippingMaskData asset belonging to the same rig. Only these generated children are replaced inside the creation Undo scope; old contour assets remain available. Genuine child Sprite layers still block creation. The remove/re-add regression check verifies one new empty contour and unchanged body data.

The clipping provider exposes the borrowed character skeleton in the body's authoring plane, allowing unbound bones to be picked. Live Transforms resolve from the same character and bone GUIDs, including sibling SpriteSkin bindings. Edit Bones is disabled on the contour renderer's Inspector; indirect Bone editor entry redirects to the real character source. Contour saving rejects changes to the borrowed skeleton.

Borrowed skeleton root and child translations, and bone lengths, all use contour pixels. Child offsets are obtained from transformed pixel positions relative to the parent's rotation, without inverting its pixel scale. Previously the scaled-parent inverse converted child offsets back to world units (for example 135.46 pixels became 1.35 at PPU 100). Auto then saw compressed bones near the lower contour even though live Scene handles showed their correct positions. Loaded contours synchronize the corrected skeleton after reload, preserving vertex weights, GUID bindings and mesh-specific reference poses. Opening a contour that was unloaded during reload also refreshes its detached provider skeleton in memory when bone GUID order is unchanged; opening alone does not save it. Reopen Edit Weights and explicitly use Auto with both desired bones selected (or no bone selection) to replace an earlier incorrect distribution; saved manual weights are not automatically regenerated.

Geometry/weights are shared by users of the same contour asset; Transform references belong to each character instance. Rig skeleton renames/additions/removals synchronize borrowed bone data and remap retained contour weights by GUID. Removed influences are dropped and remaining positive weights normalized. A vertex left with zero weight is assigned to the first retained influence; deleting the last influence leaves the contour unbound until the user binds replacement bones. The body geometry and its influence list remain untouched.

## Persistence and source boundaries

Undo-derived skeleton synchronization preserves intentionally empty contour vertex streams. The general SkinningCache image-outline fallback is cleared before saving synchronized influences, so Undo to an empty contour does not generate image geometry or throw `Sprite geometry changed. Reopen Edit Weights.` Body geometry and weights remain unchanged.

When a GameObject is deactivated (including by Undo), clipping restores the body material and disables its rendering helpers immediately. In Edit Mode, helper destruction waits until the next Editor delay callback because Unity forbids destroying components during GameObject activation/deactivation. Immediate reactivation reuses the disabled SortingGroup and clear renderer; queued cleanup leaves reclaimed helpers intact. Ordinary component disabling and authoring preview cleanup still remove helpers immediately.

Checks ran through Pipeline `run_script` with temporary preview scenes/assets, without changing the consuming manifest. The current Console reported zero errors after checks. The exact user's keyboard Undo sequence, Unity 6000.0.7 and Unity 6000.5 remain unverified for this fix; no version-sensitive API was added.

`UniskinClippingMaskData` stores the body's source Sprite as an internal coordinate-frame reference, rig reference, generated Sprite subasset, detached polygon/bone/character document, rig-to-contour transform, dependency baseline, hasGeometry flag and revision. A `<target>_ClippingMask.asset` and hidden child renderer are created on the first Draw Contour action. The polygon starts with zero vertices/triangles; the body mesh and alpha are never used as its initial shape. The internal generated Sprite supports ordinary SpriteSkin deformation, but its image does not define the mask.

`UniskinRigDataProvider` has a clipping document mode. `SceneMeshSource` routes generated contour Sprites to this mode while exposing the owning rig's source identity for live bone resolution. Unlike ordinary sprites, an empty clipping document does not fall back to the runtime Sprite quad in ReadMesh.

Scene Mesh and Weight saves update the contour asset/generated Sprite with Undo and existing meshChanged events. They do not reimport or write the source PNG/PSB. Changed external image/import settings block saving to protect authored geometry. A source image taken from the owning PSB uses that rig's existing conflict guard. PSB Bake includes only the rig's PSB layers; the clipping asset stays separate. Switching a character to PSB mode retains its binding when clipping components still need the GUID map.

The generated contour Sprite and its SpriteSkin are ordinary runtime deformation inputs. No second bone hierarchy is created. A prefab can serialize the contour authoring renderer; assigning an existing contour without one creates a transient renderer from the saved placement. Runtime bindings use the serialized UniskinRigBinding, without Editor APIs.

## Rendering and cost

URP's 2D renderer must have a depth/stencil buffer. A temporary SortingGroup isolates each target's **contour write → body → stencil clear** sequence, so overlapping characters can reuse stencil bit 128. Other custom stencil effects must reserve that bit for this workflow. The body's SpriteRenderer Sorting Layer and Order in Layer remain the authoritative settings and are never reset to local order zero. The group follows these values; contour and clear use body order −1 and +1 on the same layer. Sorting changes update only these helpers without rebuilding bone bindings; zero is handled like any other order. Disabling the mask preserves the latest SpriteRenderer sorting values. A one-time compatibility flag restores the previous order on instances created by the earlier zero-order implementation. Ordinary SpriteMask interaction is disabled for the target. A texture-mask component on the same target is suspended and restored rather than combined with independent clipping.

`Uniskin/Clipping Stencil` has Universal2D, NormalsRendering and UniversalForward passes. It writes geometry with ColorMask 0; neither its texture alpha nor a RenderTexture defines the mask. Write and clear materials use references 128 and 0. The body uses the existing lit/unlit Uniskin surface shader with stencil comparison Equal and no stencil writes. The same stencil ordering is supplied for normal rendering. Clear uses one unskinned quad covering the posed contour bounds; only the contour itself requires additional skinning.

CPU and GPU SpriteSkin paths are retained. Additional cost is contour deformation, stencil draw passes, sorting-group/batching boundaries, and a constant bounds update for the clear quad. No body triangle clipping/retriangulation or RenderTexture update runs on the CPU. This is not a promise of zero overhead or a measured many-character frame-time budget. The shared materials are not cloned per character; unchanged component updates allocate no managed memory in the focused check.

Unity 6000.5 URP declares shape lights inside LightingUtility, while the older path requires explicit declarations. `UniskinMaskLightingCompatibility.hlsl` centralizes the `UNITY_6000_5_OR_NEWER`/older branches, deriving that symbol from shader `UNITY_VERSION`. Sprite GPU vertex declarations/computation remain delegated to each installed URP Core2D include.

## Weld from character meshes

Clipping Mask Edit Weights supports **Weld** from ordinary meshes in its owning character, including the body whose Sprite ID is reused by the independent contour document. Bind at least two common bones first. Weld pulses while waiting for a Scene click on the source renderer, then offers All or Overlapping. Vertex selections, locked weights and Undo retain the ordinary Weld behavior; only the contour is saved.

`SceneWeightSession` loads a separate read-only donor context from the enabled rig provider, because the clipping provider intentionally contains only its contour. Donor candidates and weights come from that context. Contour pixels are transformed through the saved `rigToContour` inverse, contour/rig PPU and rig root offset into the same character-pixel space as the source mesh. Generated clipping renderers are excluded as donors to avoid confusing their reused Sprite ID with the body. Session teardown destroys the donor context. This does not copy geometry, modify bindings or save the body rig.
