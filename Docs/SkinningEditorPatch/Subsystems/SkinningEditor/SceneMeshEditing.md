# Scene View Mesh Editing

## Purpose and storage

The SpriteRenderer Inspector offers **Create Mesh** for an ordinary imported Sprite and **Edit Mesh** for a Sprite with explicitly authored importer geometry. Selection alone never activates Scene mesh editing or modifies an asset. Runtime triangles generated by Unity for ordinary sprites do not count as authored geometry; classification uses `ISpriteMeshDataProvider` vertices and indices. Existing geometry saved by Skinning Editor is recognized automatically.

Create Mesh stages four corners of the original SpriteRect bounding box and enters Modify mode. Edit Mesh opens the saved mesh. Both open a single floating, non-dockable UI Toolkit popup for the selected renderer. `Window > Fedorov > Uniskin > Edit Mesh` provides an explicit alternate entry for an existing authored mesh; ordinary sprites must first use Create Mesh in their Inspector. The renderer remains a standard Unity 2D SpriteRenderer. No runtime component, custom mesh asset, or instance-specific geometry is added.

Save in the exit prompt writes the selected sprite's vertices, triangle indices, explicit edges, and weights through `ISpriteMeshDataProvider`, calls `ISpriteEditorDataProvider.Apply()`, and reimports the original asset. Skinning Editor reads that same data when reopened, and all instances of the source Sprite use the resulting mesh. Other sprites in a multiple-sprite or PSD importer are left untouched. Existing bones and their full saved index order are preserved.

Changes, including initial mesh creation, are staged until Save. A pending-creation flag makes a new quad unsaved even when its positions match the Sprite's runtime rectangle. The source image is displayed as a full rectangle while authoring, including during an open New hull. The mesh outline defines the rendered Sprite after Save. Revert in the exit prompt closes the editor, discards its staged state and leaves the saved asset unchanged; reverting initial creation leaves an ordinary Sprite. There are no Apply, Revert or Frame buttons in the popup.

The popup is pinned to its entry renderer. Changing Unity selection closes it instead of automatically editing the newly selected Sprite. Pending changes prompt **Save / Cancel / Revert** before closing; Cancel restores the entry selection. Save persists to the original shared Sprite asset. Revert discards staged edits without touching the importer. The custom close tile uses the same flow. Unity's native unsaved-window handling remains available for external close requests. Closing restores Scene visibility and Unity tools and exits mesh mode.

The first implementation edits source geometry in the SpriteRenderer's local plane, independently of a SpriteSkin's current bone deformation. It does not provide a Deformed toggle or scene weight-painting window.

## Inspector registration

Unity recognizes this `Unity.2D.Animation.Editor` assembly as a Unity assembly. When multiple non-fallback inspectors target SpriteRenderer, Unity sorts equally classified assemblies by full inspector type name. The original `UnityEditor.U2D.Animation.UniskinSpriteRendererEditor` sorted after `UnityEditor.SpriteRendererEditor`, so the native Inspector won and the mesh button was absent despite successful compilation. The extension uses the product namespace `Fedorov.Uniskin`, which sorts before the native type. It remains in the same package editor assembly; no package identity or runtime type changes are required.

`DefaultSpriteRendererInspectorIncludesMeshEntry` exercises `Editor.CreateEditor(renderer)` without specifying an inspector type, asserts selection of the Uniskin extension, and checks its retained mesh button. Explicitly constructing the extension cannot detect registration regressions.

The selection ordering is documented in Unity's [6000.0 custom-editor source](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.0/Editor/Mono/CustomEditorAttributes.cs). Existing Inspector trackers can retain the old editor across script reload; rebuilding `ActiveEditorTracker.sharedTracker` refreshes that existing view without changing selection or scene data. On 2026-10-11, live diagnostics first showed the native inspector for DressFront, then showed `Fedorov.Uniskin.UniskinSpriteRendererEditor` after the fix and tracker rebuild. The user confirmed that the button appeared. Source compilation passed on Unity 6000.0.81f1; the full EditMode suite was not run.

## Window appearance

The visual baseline is Unimator's `Docs/Unimator/WindowDesignCode.md` (v0.3). This package implements it independently: opaque dark palette, square corners, one-pixel outline and button bottom stripes, 24-pixel action rows, teal active buttons, blue filled sliders, dark checkbox backgrounds, and a red close tile. The helper converts physical dimensions through `EditorGUIUtility.pixelsPerPoint`. The draggable 31-pixel header displays **Edit Mesh**, following the user's clarification; the Sprite name and duplicate content heading remain absent. There is no docked tab or second native title bar. Introductory text and shortcut/help paragraphs beneath the buttons are removed. Command failures use dialogs; temporary unavailability is exposed through the command area's tooltip.

Modify, Create, Delete, New, Reset, Generate and Trace use the user's supplied icons. The Inspector uses CreateMesh/EditMesh icons. The footer action row is removed. Window height follows the actual content block as the main controls and Trace screen replace each other; it no longer reserves 265 pixels. Option toggles use inline text with their checkbox immediately before it. Checkmark visuals are scoped to these three controls and updated from their value, including after serialized state restoration. Explicit last-button classes avoid unsupported `:last-child` selectors in Unity 6000.0.

Trace settings are a separate screen inside the same popup, not a main-screen foldout. The `mainControls` container includes command rows and display toggles; `traceSettings` includes Detail, Alpha threshold, Cancel and OK. The `mesh-hidden` class switches their visibility. The shared vertex/triangle count remains visible. The header reads **Edit Mesh: Trace** on that screen and returns to **Edit Mesh** afterward. Both screens retain the same theme and automatic height fitting.

Header dragging accepts only captured native `MouseDrag` events with the left button pressed. Synthetic pointer moves produced by panel/layout updates are ignored: their zero coordinates previously moved the popup toward the screen origin. The same event filter is used by the supplied Unimator window implementation.

After these refinements, source compilation passed on Unity 6000.0.81f1. Read-only diagnostics of the open popup reported a 340-by-165-point window, the Edit Mesh title, no footer action buttons, and checkbox ticks matching all three stored values. Dragging and visual review remain user-driven; no automated input was sent.

## Commands and input

| Control | Behavior |
| --- | --- |
| Modify | Select and drag vertices or explicit edges; Ctrl/Cmd toggles selection. Double-click a handle removes it. |
| Create | Click inside the Sprite frame to add a vertex; clicking an edge splits it. Drag from a vertex to preview an explicit edge, then release to create it. |
| Delete | Click a vertex or explicit edge to delete it. Remain in Delete after each operation until another mode is selected. |
| New | Save an entry snapshot, clear geometry and draw an open hull. Click the first vertex, press New again, or choose another mode to close it. Esc restores the entry snapshot. |
| Reset | Replace geometry with a four-corner rectangle. |
| Generate | Add a vertex at the center of each existing triangle, preserving existing positions. Repeated use increases density; capped at 10000 vertices. This deterministic Unity implementation does not reproduce Spine's adaptive placement algorithm. |
| Trace | Replace the main UI with the Trace screen and rebuild the alpha contour. Warn once on entry if the mesh has weights bound to existing bones. Detail and Alpha threshold retrace immediately, including numeric input. |
| Trace: OK | Accept the current staged contour and return to the main UI. The importer is still saved only through the exit Save prompt. |
| Trace: Cancel / Esc | Restore the complete entry session, including mesh, weights, selection, mode, pending creation and open New hull state; restore the entry slider values and return to the main UI. |
| Triangles | Show or hide dotted triangulation lines; explicit edges remain visible. |
| Dim | Darken the source image in the authoring preview. |
| Isolate | Temporarily hide other visible SpriteRenderer objects from Scene View; restore only objects hidden by this window. |
| Close / selection change: Save | Save shared Sprite asset geometry, reimport, then exit editing. |
| Close / selection change: Revert | Discard staged geometry and exit editing. |
| Close / selection change: Cancel | Keep editing and restore the entry selection when necessary. |

Drag empty space to box-select vertices; Ctrl/Cmd or Shift preserves the initial selection. Empty click and Esc clear selection outside New mode. Delete/Backspace removes selection; selecting an explicit edge's two endpoints removes that edge. Vertex deletion uses the existing boundary-stitching controller. Deletion that would leave fewer than three vertices is rejected; use New or Reset instead.

Deletion invokes the window's mutation path with `keepMode: true`. It still validates, triangulates, clears selection and records Undo, but no longer applies the generic transition to Modify; this also preserves Create when keyboard deletion is used there.

Scene Create-edge dragging owns a separate IMGUI control, distinct from the vertex/edge move sliders. The Scene host consumes the initial primary press after selection processing, preventing native picking from taking that gesture. The shared view allows action/preview checks while its own edge-drag control is hot; hover and source-local cursor positions are recomputed during captured events, including drag/repaint/release without an intervening Layout. Release creates the edge and clears capture/drag state while remaining in Create. Release back over the source or outside the frame cancels without an edge; Esc, Ignore, changing effective mode and window cleanup also release the owned control. Cleanup never releases an unrelated hot control. This behavior is gated by `useSceneHandles`; legacy Skinning Editor uses its existing uncaptured edge gesture.

Holding Alt temporarily swaps Modify and Create in Scene, using the same `SkinningEditorInput.altKeyDown` state as Skinning Editor. The toolbar highlights the effective mode; releasing Alt restores the selected mode without changing session mode, selection or Undo state. The effective mode also controls double-click deletion, so temporary Create cannot accidentally delete a vertex as Modify. Before the shared geometry controller runs, Alt is stripped from the event; leftover Alt + primary mouse events are consumed after mesh handling to prevent Scene camera panning/orbiting from stealing that gesture. Right and middle mouse retain Scene navigation, including with Alt. Delete, New and active Trace do not participate in the temporary swap; Alt navigation remains available there. New rejects a crossing or zero-area closed hull. The scene editor accepts only Simple SpriteRenderer draw mode and nonzero X/Y transform scale.

Scene GUI latches original modifier events before suppression. On Windows, an `EditorApplication.update` subscription also calls `SkinningEditorInput.Update(null)` to poll physical Alt and repaint Scene/UI when it changes, so releasing Alt over the floating popup or another window cannot leave a stale temporary mode. `Update(null)` remains a no-op on non-Windows builds, which keep the existing event-based input fallback. The update subscription is removed on disable.

Reset, New and Generate ask before removing meaningful existing weights. Trace checks weights **once on explicit mode entry**, from its button. Only enabled positive channels referencing an existing saved bone count as skinning weights; default importer weights without bones, empty weights and bones without weights do not trigger a warning. Cancel in the entry warning keeps geometry and weights unchanged and leaves the main screen visible. Accept enters Trace and rebuilding clears weights. The window serializes an entry session snapshot and entry slider values before tracing, so Cancel on the Trace screen restores geometry and bone weights even after multiple live rebuilds or a domain reload. OK accepts the staged result. Main commands are hidden and Scene geometry editing/selection is disabled during Trace; Scene navigation and drawing remain available. Esc in the popup or Scene cancels Trace. Undo that restores bone weights also exits Trace, so a later explicit re-entry can warn again. Ordinary creation interpolates weights through the shared controller. Weights stay in the importer's complete SpriteBone index space, including generated service bones; there is no Character Part influence-list remapping in this host.

Live Trace uses the same mutation, triangulation, validation and Scene repaint path as the Trace button, only while Trace is active. It does not write the importer until Save. A slider drag is collapsed into one mesh Undo group on pointer release/focus loss; releases are observed during trickle-down so the slider's own event handling cannot leave the group open. On OK, normal Trace entry and slider operations collapse into one Undo group. Cancel records the restored entry snapshot in that group before collapsing, preventing Undo from reviving a canceled intermediate preview. An explicit Undo/Redo invalidates the transaction group before further handling, so subsequent exit does not collapse an already traversed history range. **Live value-change callbacks never show modal dialogs**, including weight-loss confirmation. Both sliders immediately rebuild the mesh; Undo and exit-Revert remain available. A reentrancy guard covers mode-entry confirmation and tracing, preventing nested events during a modal entry warning. If a transient parameter value produces an empty/invalid contour, the last valid session snapshot is restored and the error is available on the Trace settings tooltip. The explicit Trace button retains its normal error dialog for failed generation. Restoring serialized slider values on window creation does not trigger a retrace. Closing with Save accepts the current Trace result before registering the separate importer-save Undo operation; closing with Revert discards the entire staged session as before.

Scene Trace starts from the package's full-detail alpha outline, then simplifies each closed contour. Concave corner removal fills small notches; convex edge collapse intersects its neighboring supporting lines to move corners outward instead of cutting across opaque image regions. An additional 0.002-texture-pixel outward allowance prevents integer clipping precision from cutting tiny slivers. Candidates must remain inside the Sprite frame, form a simple polygon and cover the original generated contour, checked with Clipper difference. Detail controls the allowed area added per collapse: `frame area * 0.02 * (1 - detail)^3`. Zero enables coarse meshes; one retains the full-detail contour. There is no forced minimum of dozens of points: a valid contour can have three vertices. Counts depend on shape and frame constraints, so Spine's seven-vertex ear example is not a universal minimum or a promised count for a different image. The Skinning Editor's existing generation algorithm is unchanged. Separate islands are simplified independently and unioned before normal shared triangulation.

Scene GUI skips rendering and editing during Trace entry/tracing or a procedural mesh mutation. Native generation/triangulation may pump editor events while arrays are being rebuilt; this guard prevents Scene triangle rendering from reading intermediate indices against an incomplete vertex array. Only the validated result or restored snapshot is exposed after mutation completes.

## Coordinate and lifetime rules

Mesh positions are relative to the selected SpriteRect, in original importer pixels. `PixelToWorld` accounts for runtime rect downscaling, pixels per unit, pivot, renderer flipX/flipY, and the complete renderer transform. The texture preview uses importer atlas coordinates, rather than runtime packed Sprite UVs.

The session is a hidden serialized ScriptableObject referenced by the window, so Undo and domain reload preserve pending edits. Apply registers importer and session Undo together; importer Undo/Redo triggers a reimport when its source fingerprint changes. Scene selection and staged geometry Undo operate on the session.

The Scene host has no SkinningCache: staged edits therefore do not emit the Sprite Editor host's `skinningCache.events.meshChanged`. That existing event path remains unchanged. Scene Apply persists through the common importer provider instead.

Before Save, the host compares the original mesh, frame, pivot and bones against freshly loaded source data. External changes require closing with Revert and reopening from the Inspector before editing again. If Skinning Editor is active on the same asset, Scene editing and saving are blocked until it is closed. This prevents competing unsaved importer caches; simultaneous live editing of one asset in both hosts is not supported in this first stage.

The window restores temporary renderer suppression, Scene visibility and the previous Unity transform tool when disabled, blocked, switching sprites or entering Play Mode. Preview material and mesh are hidden transient resources. Source mesh edits do not dirty the scene or change renderer component properties saved in the scene.
