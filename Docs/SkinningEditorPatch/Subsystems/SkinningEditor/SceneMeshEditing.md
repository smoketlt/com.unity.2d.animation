# Scene View Mesh Editing

## Suspend Skinning

The **Edit Mesh** popup offers **Suspend Skinning** for an authored mesh with a valid enabled SpriteSkin; the SpriteRenderer Inspector has no suspension button. Stop animation preview, click Suspend Skinning, move the selected image with the ordinary Unity **Move** handle, then click **Resume Skinning**. The same row replaces Suspend Skinning with **Resume Skinning** and **Cancel** side by side until the operation finishes. The popup remains open; mesh-editing controls and Scene vertex gestures pause while ordinary object Move handles are available. The current deformed shape is frozen in a temporary SpriteRenderer child, including texture coordinates, color, materials, sorting and flips. The original renderer remains hidden without disabling its SpriteSkin or changing its bone bindings. The temporary Sprite starts as an explicit FullRect rather than tracing every image in the source atlas. SetVertexCount, Position/TexCoord0 streams and SetIndices install the exact sampled mesh; OverrideGeometry is not used. Vertex count, positions, indices and UVs are checked before hiding the original, and custom local bounds retain posed vertices outside the source rectangle.

Resume uses the existing mesh-specific Update Bindings persistence path, saving the frozen geometry against the current bone Transforms while retaining weights, topology and UVs. It saves to the shared Sprite/Uniskin rig source, like Edit Weights; other instances of that shared mesh receive the new binding. The renderer's moved Transform remains a scene change and should be saved with the scene. The binding save has a separate **Resume Skinning** Undo group. Resume failures retain the preview so the user can correct the problem or cancel.

For native importer saves, a project SessionState list remembers the affected source GUIDs and binding metadata across domain reload. Undo/Redo queues reimport only when that source's userData changed, after Unity finishes restoring serialized objects. SpriteSkin refreshes its native stream cache on the normal next update. Rig Undo uses the existing generated-Sprite rebuild. With Flip X/Y, undoing only the binding save retains the moved renderer's reflection plane; undo the preceding Move as well to return to the complete entry placement.

**Cancel** restores the entry local position, rotation and scale and removes the preview without saving authoring data. Domain reload, leaving Edit Mode and shutdown also cancel. Deleting the renderer or changing its Sprite cancels on the next update. The original forceRenderingOff value is restored on cleanup, including failed initialization. Only one suspension can be active; selection stays on its mesh. Other Mesh/Bone/Weight popup entry and renderer rig-mode controls are blocked until Resume or Cancel. The owning Edit Mesh popup saves pending geometry before entering the mode, restores its ordinary preview and tool visibility, then loads the saved mesh again after Resume/Cancel. Closing that popup, Escape, domain reload or leaving Edit Mode cancels an unfinished suspension. Trace, paste, New-hull and clipping-mask modes do not offer suspension. Bound bones must lie outside the mesh object's hierarchy so moving the image cannot also move its skeleton. Clipping-mask contour sprites and animation-preview entry are unsupported.

Implementation: `SceneSkinningSuspension.cs` owns the temporary preview/session; `SceneEditMeshWindow.cs` hosts the controls declared in `SceneEditMeshWindow.uxml` (`suspendControls`, `suspendSkinning`, `resumeSkinning`, `cancelSkinning`). Source UV/index streams are copied into managed snapshots before allocating the temporary native Sprite, because native stream mutations can invalidate previously borrowed Sprite arrays. Regression cases are `SuspendSkinningMovesDisplayedImageAndPreservesWeights` in `SceneWeightEditingTests.cs`.

## Mesh Information in the Inspector

The SpriteRenderer Inspector includes an expanded **Mesh Information** foldout beneath the existing Mesh/Bones/Weights and rig controls. `SceneSpriteMeshInfo` refreshes it every 250 ms while expanded and attached to a panel; collapsing stops diagnostic sampling. It is read-only and does not enable/disable components, switch deformation systems, edit meshes/materials, create Undo entries or change project settings.

Fields include Sprite name, actual runtime vertex count, triangle count (index count / 3), registered CPU/GPU deformation mode, SpriteSkin validation state, assigned bone references versus slots and bind-pose count, global **SRP Batcher On/Off**, active render pipeline asset, Mask Interaction, local native SpriteMask enabled state, shader, Sorting Layer/order, texture dimensions and PPU. Triangle counts describe the current Sprite geometry, including Unity-generated outlines, independently of the Create Mesh/Edit Mesh authoring classification. Multiple selection totals vertex/triangle counts per renderer instance and reports **Mixed** for differing other values.

**Deformation** reads the internal `SpriteSkin.currentDeformationMethod` and requires an assigned deformation system and a ready, active skin. It does not infer CPU/GPU from SRP Batcher or global GPU eligibility. Unskinned sprites report **Static**, disabled/inactive skins **Not active**, invalid bindings **Not ready**, and a valid skin without a registered system **Not registered**. With a GPU skin and `forceCpuDeformation`, it reports **GPU + CPU copy**. SRP Batcher is a global pipeline flag, not proof that an individual sprite is batched or GPU-deformed; Built-in reports **N/A**. The native mask row reports only a SpriteMask on the inspected renderer, not all masks that could affect it.

## Selected sprite wireframe

### GPU Scene selection and contour

`SceneSpriteGpuPicking` handles ordinary Scene clicks on active, valid, registered GPU SpriteSkins. It ray-tests the current deformed Sprite triangles, including renderer flips and transforms. All eligible GPU sprites are excluded from the accompanying native pick so their undeformed silhouettes cannot steal clicks. Native non-GPU objects remain candidates. Sorting Layer, Order in Layer, nested active SortingGroups (including Sort At Root), and camera transparency sort distance resolve overlapping SpriteRenderers. Shift adds and Ctrl/Cmd toggles selection; an empty corrected click clears selection. Transform handles retain priority; Alt, View tools, other hot controls and open Mesh/Bone/Weight popups keep their input. Box selection, native pick cycling, prefab-root promotion and shader/texture-alpha or stencil clipping are not replaced by this triangle picker.

Selected GPU SpriteRenderers, including descendants of selected roots, suppress the stale native outline and draw boundary edges of their current mesh in the selection color. The global Selection Outline toggle is read through an optional cached AnnotationUtility property because it has no public SceneView property. Deselecting, switching away from GPU, opening an authoring popup, domain reload and shutdown restore the standard renderer selection flags. The replacement is a geometric contour, not Unity's alpha-derived pixel outline. No asset/component/scene data or global GPU setting is changed; no GPU readback or forced CPU deformation is used.

`SceneSpriteDeformedMesh` shares the existing bone/bind-pose/weight projection between the wireframe and picking. The wireframe retains its Create Mesh rectangle fallback; the picker and contour use the actual rendered Sprite triangles even for unauthored geometry.

Input control registration and primary clicks run in `beforeSceneGui`, before native RectSelection and Inspector scene handlers. The stable control is allocated before selection-dependent Inspector controls, and a source/deformed triangle hit registers at distance zero. A later native default control cannot replace this hit, while later actual handles can still win zero-distance ties. Using `duringSceneGui` with `AddDefaultControl` caused first-click misses; the native selection handler had already run and could supersede that default control.

`SceneSelectionOutlineCompatibility` removes only the replacement GPU renderer identities from SceneView's native parent/child outline caches **before** the camera pass. `SetSelectedRenderState(Hidden)` alone did not suppress the native Sprite outline, even when applied early. The wrapper builds the native lists using `HandleUtility.FilterEntityIds` or `FilterInstanceIDs`, preserves their actual EntityId[]/int[] types and complete child invalidation set, and invalidates the cache after the native camera pass. Other selected renderers keep their normal outlines. Object identities come from the centralized `UnityObjectCompatibility`; no IDs are narrowed. The Scene selection-outline color uses an explicit Unity 6000.5+ API branch and a pre-6000.5 preference fallback.

## Purpose and storage

For an enabled [UniskinRig](UniskinRig.md), Scene authoring resolves to its independent provider and Save updates the rig/generated Sprite subassets without PSB reimport. The native importer workflow below applies when no rig is enabled. Bake explicitly synchronizes the source PSB, and Skinning Editor entry auto-bakes.

The SpriteRenderer Inspector offers **Create Mesh** for an ordinary imported Sprite and **Edit Mesh** for a Sprite with explicitly authored importer geometry. Selection alone never activates Scene mesh editing or modifies an asset. Runtime triangles generated by Unity for ordinary sprites do not count as authored geometry; classification uses `ISpriteMeshDataProvider` vertices and indices. Existing geometry saved by Skinning Editor is recognized automatically.

Create Mesh stages four corners of the original SpriteRect bounding box and enters Modify mode. Edit Mesh opens the saved mesh. Both open a single floating, non-dockable UI Toolkit popup for the selected renderer through the Inspector buttons. There is no Window menu entry. The renderer remains a standard Unity 2D SpriteRenderer. The native importer workflow adds no runtime component, custom mesh asset, or instance-specific geometry; an enabled UniskinRig adds shared Sprite subassets and a character binding component as documented above.

Automatic saving on close writes the selected sprite's vertices, triangle indices, explicit edges, and weights through `ISpriteMeshDataProvider`, calls `ISpriteEditorDataProvider.Apply()`, and reimports the original asset. Skinning Editor reads that same data when reopened, and all instances of the source Sprite use the resulting mesh. Other sprites in a multiple-sprite or PSD importer are left untouched. Existing bones and their full saved index order are preserved.

Before writing, `SceneMeshSource.WriteMesh` compares the exact provider payload: positions, converted `BoneWeight` values, indices and explicit edges. An identical payload returns `false` without setters, Apply or reimport. Comparison uses exact position equality so small legitimate changes are retained; missing authored geometry still requires a first save even if it matches Unity's runtime quad. Session JSON also includes transient editing data, so session dirtiness alone cannot replace this check. Real edits still require reimport. See [Scene mesh save performance](SceneMeshSavePerformance.md) for measurements and the PSB limitation.

During Apply, the popup disables its controls and guards Scene drawing/input, selection-close callbacks, Undo callbacks and recursive saving. The guard and controls are restored in `finally`, including failures. The refreshed importer fingerprint is reused rather than serialized twice after saving. These guards prevent reentrant actions during native import; they do not make the import asynchronous.

Changes, including initial mesh creation, are staged until Save. A pending-creation flag makes a new quad unsaved even when its positions match the Sprite's runtime rectangle. During normal Modify/Create/Delete editing, the image is clipped to the staged mesh triangles with **Deformed** both off and on, including ordinary meshes without a saved binding pose. New hull authoring, Trace, whole-mesh paste placement and meshes without triangles retain the full source rectangle so the image remains available for authoring. The mesh outline defines the rendered Sprite after Save. Closing automatically saves valid staged changes without confirmation. Use Undo before closing to discard edits; explicit programmatic discard leaves the saved asset unchanged. There are no Apply, Revert or Frame buttons in the popup.

The popup pins Unity selection to its current editing renderer. Same-rig Scene or Hierarchy mesh switching updates that renderer and the pinned selection without closing. Other Unity selection changes restore the pinned selection without closing or prompting, including empty Scene clicks and picks intercepted by other Scene GUI handlers. Close the popup before selecting an unrelated object. Closing automatically saves pending changes to the shared source without a confirmation dialog. A failed controlled save keeps the window open. External window teardown also attempts to save; explicit discard suppresses it. Closing restores Scene visibility and Unity tools and exits mesh mode.

Primary presses are reserved in `beforeSceneGui`, before native Inspector Scene handles run. `duringSceneGui` releases only this reservation and processes the original, unconsumed event through the mesh controller. This prevents another Scene handle from selecting an overlapping object and consuming Create's click before selection restoration returns to the edited renderer. Other tools' existing hot controls, right/middle navigation and normal Alt/View navigation are left alone; temporary Alt Modify/Create still owns its primary press. Close/restore also releases only the popup's reservation. Selection restoration remains a fallback for explicit Hierarchy selection changes. See Unity's [SceneView callback ordering](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.0/Editor/Mono/SceneView/SceneView.cs).

`SceneMeshPrimaryPressIsReservedBeforePickingAndReleasedForMeshTools` checks control ownership, preservation of the original MouseDown, handoff/cleanup and navigation buttons. It does not drive the user's overlapping arm scene; that still needs an interactive check.

| Reset | Replace geometry with a four-corner rectangle. |
| Generate | Add a vertex at the center of each existing triangle, preserving existing positions. Repeated use increases density; capped at 10000 vertices. This deterministic Unity implementation does not reproduce Spine's adaptive placement algorithm. |
| Trace | Replace the main UI with the Trace screen and rebuild the alpha contour. Warn once on entry if the mesh has weights bound to existing bones. Detail and Alpha threshold retrace immediately, including numeric input. |
| Trace: OK | Accept the current staged contour and return to the main UI. The source is saved on close. |
| Trace: Cancel / Esc | Restore the complete entry session, including mesh, weights, selection, mode, pending creation and open New hull state; restore the entry slider values and return to the main UI. |
| Triangles | Show or hide dotted triangulation lines; explicit edges remain visible. |
| Deformed | Follow the live SpriteSkin bone pose while retaining source-space edits and Undo. |
| Outside Bounds | Permit vertex and edge movement outside the bounding box while keeping the box visible; unchecked by default. |
| Dim | Darken the source image in the authoring preview. |
| Isolate | Temporarily hide other visible SpriteRenderer objects from Scene View; restore only objects hidden by this window. |
| Close | Automatically save valid staged geometry, then exit. A failed controlled save keeps the window open. Use Undo before closing to discard edits. |
| Unity object selection change | Restore the opening selection without prompting or discarding staged edits. |

Drag empty space to box-select vertices; Ctrl/Cmd or Shift preserves the initial selection. Empty click and Esc clear selection outside New mode. Delete/Backspace removes selection; selecting an explicit edge's two endpoints removes that edge. Vertex deletion uses the existing boundary-stitching controller. Deletion that would leave fewer than three vertices is rejected; use New or Reset instead.

While editing in Scene View, the cursor follows the effective mode: Modify uses an arrow with the move symbol, Create and New use an arrow with a plus, and Delete uses an arrow with a minus. Alt's temporary Modify/Create swap updates the cursor too. Cursor registration runs after mesh handles so their slider cursors do not replace the mode indicator. Trace does not register an editing cursor; right/middle mouse and unswapped Alt navigation retain native Scene cursor routing. These are built-in `MouseCursor` values registered through `EditorGUIUtility.AddCursorRect`, shared by Unity 6000.0 and 6000.5+.

After mesh and rectangle-selection handling, the Scene host consumes remaining primary mouse presses, drags and releases, including clicks outside the Sprite frame and in New mode. The default IMGUI control alone cannot guarantee ownership when another Scene handle wins `nearestControl`. Invalid vertex placement remains a no-op; it cannot become native object picking or an exit prompt. Right/middle navigation and Alt navigation outside the temporary Modify/Create swap retain their existing routing.

Deletion invokes the window's mutation path with `keepMode: true`. It still validates, triangulates, clears selection and records Undo, but no longer applies the generic transition to Modify; this also preserves Create when keyboard deletion is used there.

Scene Create-edge dragging owns a separate IMGUI control, distinct from the vertex/edge move sliders. The Scene host consumes the initial primary press after selection processing, preventing native picking from taking that gesture. The shared view allows action/preview checks while its own edge-drag control is hot; hover and source-local cursor positions are recomputed during captured events, including drag/repaint/release without an intervening Layout. Release creates the edge and clears capture/drag state while remaining in Create. Release back over the source or outside the frame cancels without an edge; Esc, Ignore, changing effective mode and window cleanup also release the owned control. Cleanup never releases an unrelated hot control. This behavior is gated by `useSceneHandles`; legacy Skinning Editor uses its existing uncaptured edge gesture.

Holding Alt temporarily swaps Modify and Create in Scene, using the same `SkinningEditorInput.altKeyDown` state as Skinning Editor. The toolbar highlights the effective mode; releasing Alt restores the selected mode without changing session mode, selection or Undo state. The effective mode also controls double-click deletion, so temporary Create cannot accidentally delete a vertex as Modify. Before the shared geometry controller runs, Alt is stripped from the event; leftover Alt + primary mouse events are consumed after mesh handling to prevent Scene camera panning/orbiting from stealing that gesture. Right and middle mouse retain Scene navigation, including with Alt. Delete, New and active Trace do not participate in the temporary swap; Alt navigation remains available there. New rejects a crossing or zero-area closed hull. The scene editor accepts only Simple SpriteRenderer draw mode and nonzero X/Y transform scale.

Scene GUI latches original modifier events before suppression. On Windows, an `EditorApplication.update` subscription also calls `SkinningEditorInput.Update(null)` to poll physical Alt and repaint Scene/UI when it changes, so releasing Alt over the floating popup or another window cannot leave a stale temporary mode. `Update(null)` remains a no-op on non-Windows builds, which keep the existing event-based input fallback. The update subscription is removed on disable.

Reset, New and Generate ask before removing meaningful existing weights. Trace checks weights **once on explicit mode entry**, from its button. Only enabled positive channels referencing an existing saved bone count as skinning weights; default importer weights without bones, empty weights and bones without weights do not trigger a warning. Cancel in the entry warning keeps geometry and weights unchanged and leaves the main screen visible. Accept enters Trace and rebuilding clears weights. The window serializes an entry session snapshot and entry slider values before tracing, so Cancel on the Trace screen restores geometry and bone weights even after multiple live rebuilds within the open session. Domain reload discards the staged result and closes the popup. OK accepts the staged result. Main commands are hidden and Scene geometry editing/selection is disabled during Trace; Scene navigation and drawing remain available. Esc in the popup or Scene cancels Trace. Undo that restores bone weights also exits Trace, so a later explicit re-entry can warn again. Ordinary creation interpolates weights through the shared controller. Weights stay in the importer's complete SpriteBone index space, including generated service bones; there is no Character Part influence-list remapping in this host.

Live Trace uses the same mutation, triangulation, validation and Scene repaint path as the Trace button, only while Trace is active. It does not write the importer until Save. A slider drag is collapsed into one mesh Undo group on pointer release/focus loss; releases are observed during trickle-down so the slider's own event handling cannot leave the group open. On OK, normal Trace entry and slider operations collapse into one Undo group. Cancel records the restored entry snapshot in that group before collapsing, preventing Undo from reviving a canceled intermediate preview. An explicit Undo/Redo invalidates the transaction group before further handling, so subsequent exit does not collapse an already traversed history range. **Live value-change callbacks never show modal dialogs**, including weight-loss confirmation. Both sliders immediately rebuild the mesh; Undo and exit-Revert remain available. A reentrancy guard covers mode-entry confirmation and tracing, preventing nested events during a modal entry warning. If a transient parameter value produces an empty/invalid contour, the last valid session snapshot is restored and the error is available on the Trace settings tooltip. The explicit Trace button retains its normal error dialog for failed generation. Restoring serialized slider values on window creation does not trigger a retrace. Closing with Save accepts the current Trace result before registering the separate importer-save Undo operation; closing with Revert discards the entire staged session as before.

Scene Trace starts from the package's full-detail alpha outline, then simplifies each closed contour. Concave corner removal fills small notches; convex edge collapse intersects its neighboring supporting lines to move corners outward instead of cutting across opaque image regions. An additional 0.002-texture-pixel outward allowance prevents integer clipping precision from cutting tiny slivers. Candidates must remain inside the Sprite frame, form a simple polygon and cover the original generated contour, checked with Clipper difference. Detail controls the allowed area added per collapse: `frame area * 0.02 * (1 - detail)^3`. Zero enables coarse meshes; one retains the full-detail contour. There is no forced minimum of dozens of points: a valid contour can have three vertices. Counts depend on shape and frame constraints, so Spine's seven-vertex ear example is not a universal minimum or a promised count for a different image. The Skinning Editor's existing generation algorithm is unchanged. Separate islands are simplified independently and unioned before normal shared triangulation.

Scene GUI skips rendering and editing during Trace entry/tracing or a procedural mesh mutation. Native generation/triangulation may pump editor events while arrays are being rebuilt; this guard prevents Scene triangle rendering from reading intermediate indices against an incomplete vertex array. Only the validated result or restored snapshot is exposed after mutation completes.

## Coordinate and lifetime rules

Scene Edit Mesh accepts Create clicks (including temporary Alt-Create), Modify double-click creation, New hull clicks and Create edge-drag releases outside the bounding box. Vertices remain at the clamped frame position shown by the preview; moving the cursor farther outside does not cancel creation. Sprite Editor frame checks are unchanged. Verify all four borders/corners, Undo and edge-drag release outside the frame. Input regression cases cover Scene versus Sprite Editor clicks and captured outside-frame release; they have not been executed in Unity for this revision.

After saving fully cleared weights with existing bones, the imported Sprite uses a runtime-only rigid first-bone fallback to remain visible. Provider weights stay empty, so subsequent weight authoring starts unbound. Assign explicit weights to restore deformation. This applies to Trace, Reset, New and Generate and to both full and cached PSB imports; see [Mesh data and weights](MeshDataAndWeights.md#rendering-fully-cleared-weights).

Mesh positions are relative to the selected SpriteRect, in original importer pixels. `PixelToWorld` accounts for runtime rect downscaling, pixels per unit, pivot, renderer flipX/flipY, and the complete renderer transform. The texture preview uses importer atlas coordinates, rather than runtime packed Sprite UVs.

Edit Mesh outlines the full source-image rectangle when Deformed is off. With Deformed on, the frame uses the tight min/max bounds of the same posed vertices used by the image preview, recomputed each repaint so toggling and animation update it immediately. This display-only bound does not change the source frame or editing limits. New, Trace and paste retain the source rectangle. The outline uses a repeating gray dash / gap / dark-gray dash / gap pattern. Dashes are 6 physical screen pixels long with 3-pixel gaps and a 1.5-pixel line width, independent of Scene zoom and display scaling. The pattern continues through all four corners, follows the same source-pixel transform as the preview (including rotation, scale and renderer flips), and remains visible in New and Trace and with Triangles disabled. The frame is drawn over the image and beneath mesh handles. Viewport clipping limits dash generation to visible portions when zoomed in; source rectangles crossing behind the camera are skipped.

Physical appearance and Unity 6000.0/6000.5 execution remain unverified; no version-sensitive API was added.

The session is a hidden serialized ScriptableObject referenced by the window so Undo preserves pending edits while it is open. Domain reload closes the popup as described below. Apply registers importer and session Undo together; importer Undo/Redo triggers a reimport when its source fingerprint changes. Scene selection and staged geometry Undo operate on the session.

The Scene host has no SkinningCache: staged edits therefore do not emit the Sprite Editor host's `skinningCache.events.meshChanged`. That existing event path remains unchanged. Scene Apply persists through the common importer provider instead.

Before Save, the host compares the original mesh, frame, pivot and bones against freshly loaded source data. External changes require closing with Revert and reopening from the Inspector before editing again. If Skinning Editor is active on the same asset, Scene editing and saving are blocked until it is closed. This prevents competing unsaved importer caches; simultaneous live editing of one asset in both hosts is not supported in this first stage.

The window restores temporary renderer suppression, Scene visibility and the previous Unity transform tool when disabled, blocked, switching sprites or entering Play Mode. Preview material and mesh are hidden transient resources. Source mesh edits do not dirty the scene or change renderer component properties saved in the scene.

## Domain reload and restored windows

Edit Mesh, Edit Bones and Edit Weights share `SceneEditWindow`. Before an assembly/domain reload, it closes the popup without saving or showing a modal confirmation. Each host's `OnDisable` skips auto-save and releases Scene/selection/Undo/update callbacks, renderer suppression, visibility and tools; `OnDestroy` destroys the hidden session. Unsaved staging is discarded. Closure errors are logged to the Console and any surviving window is destroyed in `finally`. An orphan without a host panel is destroyed directly. Controlled user close retains its existing save behavior.

An open popup recovered from a Unity startup layout or a reload is scheduled to close on the next editor delay callback. Its serialized lifetime marker, or existing renderer/session for older layouts, identifies restoration. `OnEnable` skips session reconstruction and callback registration, and `CreateGUI` skips UI setup. Restored windows do not try to save incomplete session state. The tool scope is created lazily so an absent transient helper cannot throw in Scene callbacks or cleanup. Weight preferences remain in EditorPrefs and are restored when explicitly reopening from the Inspector; mesh/bone selections and transient modes end with the session.

`Tests/Editor/SceneEditWindowTests.cs` covers all three popups: forced reload close despite Unity's unsaved marker, destruction of hidden sessions, restoration of tool/handle state, a restored window missing its session, and older layouts missing the lifetime marker. Manual reload checks should verify closure, normal object selection and no recurring Scene GUI exceptions; restarting Unity should not leave these popups open.
