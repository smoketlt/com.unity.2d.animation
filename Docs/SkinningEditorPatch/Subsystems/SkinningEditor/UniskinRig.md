# UniskinRig authoring and PSB baking

## Storage and activation

UniskinRig separates geometry, skeleton, per-layer influences and weights from PSB image import. A single `UniskinRig` ScriptableObject is authoritative for one source PSB while enabled. Its source GUID survives asset moves. Its detached authoring document retains Sprite IDs, SpriteRects, complete SpriteBone index order, vertices, weights, indices, edges, CharacterData and namespaced weight/draw-order metadata. Texture, outlines, source layering and texture import settings remain owned by the PSB.

The SpriteRenderer Inspector and the scene character root's GameObject Inspector expose one three-button block for PSB sources: **Use Uniskin rig** and **Use PSB Importer** share a row, followed by full-width **Bake to PSB Importer**. All three remain visible. The current mode button is disabled; the alternative mode button is available outside Play Mode (and only for single-object inspection). Bake is enabled only when the rig has unbaked changes and does not switch the active mode. The buttons use the supplied `UniskinLogo.png`, `PsbLogo.png` and `BakeToPsb.png` resources. Root lookup accepts one PSB source within the same binding/prefab root, including characters without bones, and rejects ambiguous sources; it does not add rig controls to individual bone headers.

**Use Uniskin rig** creates `<source>_UniskinRig.asset` alongside the source when needed and updates loaded character instances. When switching an existing disabled rig back from PSB mode, it first copies the current native mesh, bones, weights and character metadata into the rig before activating it. Selection and Inspector polling never create or reload a rig. Ordinary imported Sprite workflows continue to use their native importer. External shared skeletons must be detached/baked at their own source before creating a rig.

The asset contains persistent generated Sprite subassets cloned from the imported Sprites. They share the imported texture/atlas and retain native rendering information; geometry and bones use the same authoring-to-runtime conversion as PSB postprocessing. Scene Mesh/Bone/Weights resolve both source and generated Sprites back to the original PSB identity and use a detached provider adapter for staged changes. Save updates the rig and its generated Sprites without calling PSB Apply or SaveAndReimport. The original image bytes and importer metadata remain unchanged until baking.

Scene Edit Weights [Update Bindings](SceneWeightEditing.md#update-bindings) persists a mesh-specific pose and retained texture mapping in the document's namespaced userData. Generated Sprite rebuilds restore these matrices/UVs after ordinary texture-coordinate recovery; Bake copies the metadata so native PSB imports restore the same binding. Shared character bones and other meshes' references are unchanged.

This mesh-specific reference is restored by this fork's import hooks; the standard shared character skeleton still describes the original source bones. Ordinary native importer bone fields alone do not represent the extra binding/texture mapping.

## Scene and runtime bindings

### Binding Inspector rendering mode

**Always Show Bones** in the `UniskinRigBinding` component Inspector keeps this instance's bones visible in Scene view without selecting it. The serialized boolean defaults to off, supports Undo/multi-object editing and scene/prefab persistence, and requires Scene Gizmos. It affects editor display only. See [Skeleton Bone Editing](SkeletonBoneEditing.md#bone-display-size).

`UniskinRigBinding` uses the supplied Uniskin logo as its script icon. Its **GPU Skinning (Project)** dropdown is a shortcut to the global Player > Other Settings setting, using `PlayerSettings.meshDeformation`. It exposes **CPU**, **GPU**, and **GPU Batched** without collapsing an existing GPU mode. GPU Batched is the equivalent of enabling the legacy GPU Skinning checkbox. Changes affect the whole project, not just the selected rig, and edits made in Player Settings are reflected back into the Inspector. No per-binding runtime override is stored.

The Inspector reports actual registered deformation modes, including inactive/not-ready skins and mixed renderer results. GPU deformation additionally requires URP/SRP Batcher, platform support and a compatible material/shader. SpriteSkin **Force CPU Deformation** requests an additional CPU copy while GPU is active; it is not the CPU backend selector. **Always Update** controls offscreen deformation. Vertex/bone counts, character count and visibility affect workload. These remain SpriteSkin settings rather than being overwritten by the binding.

The UI Toolkit component Inspector is implemented by `SceneMesh/UniskinRigBindingEditor.cs`. `PlayerSettings.meshDeformation` is available on both Unity 6000.0 and 6000.5+, so the shortcut does not use the deprecated `gpuSkinning` API or require a version branch.

The diagnostic restored the original Player setting and removed its temporary objects/UI. Unity 6000.0 execution and visual GPU output were not repeated for this change. The consuming project uses a local file dependency and recompiles directly from this checkout.

`UniskinRigBinding` is serialized on each loaded character root. It maps bone GUIDs to existing Transforms, preserves existing scene poses, creates missing bones with Undo, and assigns the generated Sprites and SpriteSkin Transform arrays. Rig saves affect loaded instances of the same source. Newly instantiated source characters are attached through the editor hierarchy update. Each character must have its own root; a single binding root cannot represent two PSB rigs.

The binding runs after SpriteResolver and before SpriteSkin, so source Sprite Library swaps are mapped to the corresponding generated Sprite. Scenes containing the component and generated Sprite references use the rig in players without Editor APIs. **Create Rig Prefab** creates a regular prefab snapshot of a loaded rig character for runtime instantiation; instantiating an unchanged PSB prefab directly in a player uses its baked PSB data. When a saved rig prefab predates later changes, the runtime binding creates new bones and missing SpriteSkin components, updates authored pose deltas and hierarchy, and removes obsolete bones while preserving their remaining children. An older rig prefab also resolves the baked skeleton on load after the asset switches to PSB mode.

Existing Transforms retain their identity. Set Parent (including detaching to the character root) preserves the existing bone's world position and rotation when saving to a rig, including a posed instance and an older prefab adopting a changed rig hierarchy at runtime. Movement after Set Parent must also persist: simply keeping the previous scene pose loses that edit. Before changing any Transform or stored baseline, shared `UniskinRigBinding.CaptureHierarchyPoses` reconstructs old/new source world matrices and transfers each bone's authored delta through its current scene-pose conversion. Both the Editor and runtime apply these captured world poses in the new hierarchy, including descendants. Source parent identities are compared by GUID, so numeric reordering alone is not a hierarchy change; an actual scene/source parent mismatch is handled as well. New bones still initialize from the source pose. The stored source-pose baseline advances after reparenting so a repeated refresh does not apply the parent-coordinate change again. Removing an earlier bone may change numeric parent indices without changing the parent Transform; that case preserves the surviving bone's scene pose. Sprite-layer GameObjects are excluded when locating an unbound skeleton Transform. Bone rename animation-path validation remains shared with Scene Edit Bone. Closing a Scene Mesh/Bone/Weights popup or switching tools automatically saves its valid staged changes without a confirmation dialog. Delayed fields commit before saving; a failed controlled close keeps the tool open and reports the error. An external window teardown also attempts to save pending data and logs any failure. Explicit programmatic discard suppresses that fallback. Saving to the enabled rig does not import the PSB, and newly saved bones are available to Edit Weights immediately.

## Bake and return to the native workflow

### Scene hierarchy synchronization and prefab instances

An applied Sprite revision is not proof that scene bones are synchronized. In Edit Mode, `UniskinRigBinding.Apply`/`OnEnable` can acknowledge the revision without updating bone GameObjects. `RefreshInstances` skips work only when GUID order, source-pose baselines and actual Transform parents also match. A deferred refresh after domain reload repairs existing mismatches; Undo/Redo also runs the full scene synchronization.

Unity does not allow an inherited prefab bone to change parent, and `Undo.SetTransformParent` can leave the parent unchanged without throwing. When a saved rig requires such a change, `EnsureBone` first unpacks the affected scene prefab instance completely with Undo, retaining the same GameObjects, overrides and references, then reparents and verifies the actual Transform parent. Nested inherited prefab ownership is removed only as needed to permit that bone's move. Ordinary pose edits, unchanged hierarchies and reparenting added GameObject overrides do not require unpacking. The rig asset and source PSB remain linked through the rig's source GUID, but the unpacked scene character no longer receives prefab-instance updates from that prefab. Source PSB assets are not unpacked or rewritten. A normal bone save groups this operation with its source change; Undo restores the previous parent and prefab connection, and Redo reapplies the change.

The source/scene pose snapshot is captured before unpacking or reparenting. This retains scene poses and movement after Set Parent, including descendants. A failed parent assignment now raises an error instead of silently marking the binding synchronized.

**Bake to PSB Importer** is available in the renderer and root Inspectors; the rig asset Inspector retains its advanced controls and **Bake to PSB** command. Baking automatically saves and closes active Scene tools, validates the complete rig document, writes mesh/bone/character data through the native Sprite Editor providers, preserves other import settings, and reimports once. The Photoshop image bytes are not rewritten: standard Skinning Editor data is stored in the PSB importer metadata, as with native Apply.

Bake verifies the reloaded authoring payload before marking the rig synchronized. If verification/import fails, it attempts to restore the previous importer serialization and keeps the rig unbaked. Generated Sprite IDs remain stable during normal rig saves. During PSB prefab regeneration, newly generated duplicate bones are reconciled with the authored scene Transforms to retain scene/animation references.

Explicit **Bake to PSB Importer** / **Bake to PSB** commands offer **Force Bake** or **Cancel** when a source conflict is detected. Force Bake treats the saved rig as authoritative and bypasses source hash/native-baseline conflict checks; it also writes when the rig was previously marked synchronized. It retains document validation, tool-close/save requirements, native import verification and importer rollback. External importer skinning edits and the replaced rig metadata are overwritten; Photoshop image bytes are preserved. Source layer reconciliation is still unsupported. Automatic baking and mode switching retain their normal conflict protection. Bake baseline comparison uses the same current-serializer normalization as editing, so equivalent JSON formatting does not cause a false conflict.

Entering the Skinning Editor module on an enabled source PSB automatically runs the same bake before creating its cache. **Open Skinning Editor (Auto Bake)** remains available in the rig asset Inspector; the renderer/root block has no additional Skinning Editor button. Synchronized rigs skip reimport. A synchronization failure leaves the Skinning module blocked and explains the source conflict instead of allowing edits to stale PSB data.

**Use PSB Importer** (named **Bake and Use PSB** in the rig asset Inspector) bakes pending changes before switching, returns loaded renderers to the source Sprites, retains ordinary SpriteSkin bindings and removes their rig binding components. Renderer and SpriteSkin changes are recorded as prefab overrides. The rig asset remains as a backup. Switching back with **Use Uniskin rig** refreshes it from PSB as described above. **Reload from PSB** explicitly replaces rig authoring data with current native data and refreshes the generated Sprites; unbaked changes require a discard confirmation. Successful native PSB imports refresh a synchronized rig through a deferred postprocessor; unbaked rigs are never silently overwritten. Imported bone poses already applied by prefab regeneration advance the binding baseline, preventing the same movement from being applied twice.

## Conflicts and Undo

Source dependency hashes, a SHA-256 hash of the PSB file and the captured native authoring baseline protect against external PSB changes. Dependency hashes can change when moving a complete asset folder (including `.meta` files) between projects or changing importer dependencies. On a dependency mismatch, editing/baking is permitted only when native authoring data still matches the baseline and the stored file hash still matches. Baselines are deserialized and reserialized with the current Unity serializer before comparison: decimal formatting changes between Unity versions must not count as source edits. This uses exact stored float values, without a numerical tolerance. Invalid baselines remain conflicts. The dependency hash is then refreshed without replacing rig authoring data or baking. Legacy rigs without a file hash are adopted using their native baseline; historical image-only changes cannot be detected during that first adoption. Rigs with a matching dependency hash acquire a missing file hash as well. Creation, reload and bake capture both hashes. A changed source blocks rig save/bake until the source is restored or the rig is explicitly reloaded. Source layer creation/removal is outside this initial adapter and requires a new rig after backing up the old one. Duplicate rigs referencing one PSB are rejected rather than selected arbitrarily.

Staged editing continues to use the existing mesh/skeleton Undo scopes and events. Rig saves record the asset, native Sprite subassets, bindings, bone creation and affected scene objects; failed saves revert their scene update group. The original PSB is not reimported by Undo of a rig mesh save, including after the rig lookup cache has been invalidated. Bake records the source importer through its normal Unity Undo lifecycle.

Scene binding synchronization takes complete Undo snapshots of `UniskinRigBinding` and changed bone Transforms. `Undo.DestroyObjectImmediate` and hierarchy operations can flush pending `Undo.RecordObject` diffs before synchronization assigns its final GUID array, source-pose baselines or post-reparent pose. Recording only a diff can therefore leave a shortened/reordered binding array after undoing a bone deletion saved on Edit Bones close. The subsequent synchronization can then interpret scene poses against the wrong baseline. Complete snapshots cover the whole operation, including assignments after that flush.

Every generated Sprite rebuild explicitly restores `TexCoord0` after native geometry replacement. Undo can restore a native Sprite with cleared UV streams; relying on importer-time UV generation made all character layers sample the transparent atlas origin. It never samples the potentially damaged generated Sprite's UVs or changes source image/provider data. After domain reload, enabled rigs with all-zero generated UV streams receive the same derived-data repair and their SpriteSkin bindings refresh.

## Source routes

- `Runtime/UniskinRig.cs`: persistent authoring document, source identity and generated Sprite references.
- `Runtime/UniskinRigBinding.cs`: player-compatible Sprite/GUID binding.
- `Editor/SkinningModule/SceneMesh/UniskinRigDataProvider.cs`: detached authoring document and provider adapter.
- `Editor/SkinningModule/SceneMesh/UniskinRigUtility.cs`: create/save/bake, conflicts, scene reconciliation, source refresh and rig prefab creation.
- `Editor/SkinningModule/SceneMesh/UniskinRigEditor.cs`: rig Inspector controls.
- `Editor/SkinningModule/SceneMesh/UniskinRigInspectorControls.cs`: renderer/root three-button layout, icons, mode/bake availability, unique root source lookup and delayed commands; `SceneBoneInspector` hosts root controls in the native GameObject header.
- `SceneMeshSource`, Scene Bone/Weight sessions and Scene windows: source routing and rig save integration.
- `Editor/SpritePostProcess.cs`: shared native conversion.
- `SkinningModule.OnModuleActivate`: automatic bake before cache creation.
- `Tests/Editor/UniskinRigTests.cs`: persistent native Sprite round-trip, source preservation, new bones/weights, explicit/automatic baking, conflicts and Undo.
