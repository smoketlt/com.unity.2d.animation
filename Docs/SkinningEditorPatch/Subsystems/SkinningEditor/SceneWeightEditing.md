# Scene View Weight Editing

## Entry and scope

For an enabled [UniskinRig](UniskinRig.md), Save persists weights, bindings and draw ranks in the rig and updates its generated Sprite subassets without PSB reimport. The native importer workflow described below applies when no rig is enabled; Bake transfers the same provider payload to PSB.

The SpriteRenderer Inspector exposes **Edit Weights** below Edit Mesh and Edit Bone when the Sprite has authored importer geometry. This button opens the floating UI Toolkit popup; there is no Window menu entry. The popup is pinned to its entry renderer and locks Unity object selection to the opening selection until explicitly closed. Empty Scene clicks and selecting another object restore that selection on the next editor update; they never request closing or display a save prompt. Merely selecting an object does not activate the host.

The window follows Edit Mesh/Bone's dark styling, draggable title and red close button. Drag its bottom edge grip to resize height; the scrollable bone list fills the available space. Supplied `Weights.png`, `Smooth.png`, `Bind.png`, `Auto.png`, `Prune.png`, `Swap.png`, `Weld.png` and `Delete.png` are used; Delete is assigned to Remove. Influence and Update are absent.

Position, size, chosen mode, Strength/Size/Feather and Pieces/Overlay/Selected are saved in per-project EditorPrefs under `Unity.2D.Animation.SceneEditWeights.<Application.dataPath>`. New openings restore them; domain reload retains the window's serialized settings. Saving preferences runs on control changes, on close and periodically while open to capture dragging/resizing, and only writes when values change. Bind, gestures, bone/vertex selections and bone locks are session state and are not carried to another mesh. Corrupt/non-finite preferences are ignored and slider values are clamped to their ranges.

Rows, sliders, viewport bones, pieces and overlay share `BoneColorUtility.GetWeightMapColor`, the fixed Skinning Editor weight palette. Row slider fills match their bone, use the numeric field's height and hide the dragger/end marker. Locked swatches use the same embedded lock texture as `WeightInspector`, rather than a text glyph. Bone-name pointer handling runs in the trickle-down phase so the built-in Button manipulator cannot consume plain clicks before selection.

Rows have a fixed, non-shrinking height. Swatches are 20 by 20 physical pixels, inset 4 pixels from the dark list edge; bone names start 4 pixels after the swatch and use left text alignment with no internal horizontal padding. Name-column widths follow the Swap button's left world-coordinate, keeping every bone track aligned to that edge after layout/resizing. Slider input, drag container, tracker and numeric field heights are pinned inline to 20 physical pixels (scaled by pixelsPerPoint), including minimum/maximum height and zero vertical margins/padding. This overrides Unity's more specific horizontal-slider rules that kept the visible track near 13 pixels despite the earlier USS changes. Slider drag containers stretch across their available width. Do not center the drag container with `align-self: center`: its content is positioned absolutely, so its intrinsic width can collapse and hide both the tracker and fill while leaving the numeric field visible. Tracker top/bottom offsets and margins are explicitly aligned to the container; the default thin-slider centering offset must not remain on a full-height fill, because that makes it overlap the next row after resizing.

| Strength | Floating-point signed stamp amount, 0–100 percent. Fractional values remain fractional in brush and Direct calculations. |
| Size | Floating-point brush radius in source pixels, 1–500, projected into the Scene View. |
| Feather | Floating-point linear falloff outside the inner circle, 0–100 percent. |
| Bone name in popup | Click an unselected bone to select it; Ctrl/Cmd/Shift adds to the selection. Clicking an already selected row removes that bone, including with a plain click. |

Undo restores the order. Bone depths, weights, indices into the skeleton and palette colors are unchanged. |
| Bone swatch | Lock/unlock that bone's weights for painting, row edits, Smooth, Auto, Prune and Swap. Locks are session UI state, not runtime data. |

| Direct: double-click empty space | Clear vertex selection only, retaining selected bones and keeping Edit Weights open. Does not alter weights or dirty the staged mesh. |

| Ctrl/Cmd+drag | Rectangle-select vertices starting outside bones; preserve the previous vertex selection. |
| Alt held in Add | Temporarily paint Remove; the Mode field reflects the effective mode without changing the chosen mode. Release Alt to return to Add. |
| Smooth | Reuse the Sprite Editor Weight Slider's snapshot neighborhood pass, including inverse edge length weighting and 45% blend. Selected vertices restrict the target set. Two or more selected bones restrict the channels; otherwise use all bound unlocked bones. |
| Auto | Use Unity's bounded biharmonic generator in source/bind space. Selected vertices restrict writes; selected bound bones restrict the generator's bone set. Both restrictions apply together. Preserve locked weights. |
| Prune | Threshold / maximum-bone popup styled with the same Scene window header, sliders and buttons; preview the channel removal count and apply on confirmation. Preserve locked weights and never prune to an empty weight set. Sprite Editor's existing utility UI remains available to its callers. |
| Bind | Toggle binding mode and click unbound skeleton bones to add them to this mesh. Unbound candidates are neutral gray at 100% opacity; already bound bones are dark gray at 40% opacity and inactive. The active button retains its selected color and a separate highlight fades smoothly from zero to full opacity and back over a two-second cycle; the icon and label remain opaque. The pulse stops immediately on exiting Bind or when editing is blocked. Preserve existing positive weights and initialize only vertices with no weights. |
| Swap | Enabled for exactly two selected unlocked bound bones. Exchange their channels on selected vertices, or all vertices without a selection. |
| Weld | Choose another character mesh as the weight source, then All or Overlapping. Transfer into the current mesh, respecting selected vertices and locked weights. Requires two common bound bones. |
| Remove | Unbind selected bones from this mesh; retain the skeleton itself. Normalize surviving weights; vertices with no surviving channels receive weights across up to four remaining bound bones. At least one bound bone must remain, because otherwise there is no recipient for redistribution. |
| Esc | End the active gesture, leave Bind and clear vertex selection immediately, retaining selected bones. End any pending temporary vertex selection before clearing the committed set. Bone deselection belongs to the popup list, not Scene Escape. Claim KeyDown in `SceneView.beforeSceneGui`, ahead of other tools' `duringSceneGui` callbacks. The later raw-event fallback skips cancellation if the earlier phase handled that press, avoiding double unselection. Consume the key in both Scene and popup UI; keep the window and editing mode active, even when nothing is selected. |
| Add/Remove: primary empty click without paint targets | Preserve selected bones. |
| Middle/right mouse | Preserve Scene navigation. Ctrl/Cmd+primary selects vertices; Alt+primary in Add paints Remove. |

**Pieces** switches vertex visuals: enabled displays weighted pie handles; disabled displays small solid cyan dots without weight sectors. Dots have a 2-physical-pixel radius, increasing to 3 pixels for selected vertices with a white selection outline. Both visuals retain the same 12-physical-pixel picking radius, Ctrl/Cmd and rectangle selection, Direct weight drags and popup row editing. Changing Pieces preserves selections and weights. Sectors always follow the displayed bone list order, starting from the same up direction. They use the summed weight for each bone rather than the underlying channel order, so crossing weight values does not swap colors around the vertex. Explicitly reordering rows also changes sector order. **Overlay** fills the preview mesh with interpolated bone colors. **Selected** hides pies or dots without weight on selected bones, except explicitly selected vertices; unselected bone contributions become black in Overlay. Selected bone colors remain proportional to their actual weights. Direct hit testing follows the Selected filter; Ctrl selection still operates on the full mesh, including when Pieces is disabled.

Outside Bind, viewport bones outside the current mesh's binding list are neutral gray at 25% opacity, without weight-palette colors or selection emphasis. Ordinary editing excludes them from bone hit testing. Bind raises these unbound candidates to 100% opacity and permits picking only them; already bound bones fade to dark gray at 40% opacity. After binding, a bone immediately fades and becomes inactive for further Bind clicks, then receives its palette color when Bind is switched off. This is a display/input restriction and does not change the shared skeleton or other meshes' bindings.

The viewport always draws mesh boundary edges in cyan and authored internal vertex-to-vertex edges in orange, following the Spine weight-editing reference. Boundary edges come from `mesh.outlineEdges`; explicit constraints come from `mesh.edges`. Boundaries draw over any matching authored edges so the perimeter stays cyan. Automatic interior triangulation edges remain hidden. Lines follow the same deformed screen positions as the weight pies and draw behind bones and pies. Pieces, Overlay, Selected and Scene Gizmos do not hide these mesh lines; the lines add no picking controls or staged changes.

The Scene View's Gizmos toggle controls bone bodies/nodes and their viewport hit testing in Edit Weights, independently for each Scene View. Hidden bones cannot intercept brush or vertex-selection clicks, including Bind clicks. Bone selection through the popup list, mesh preview, Pieces, Overlay and brush controls remain available with Gizmos off. The toggle does not clear bone selection or exit the editing session.

## Introducing an influence at the four-weight limit

Direct drags, Add brush stamps and bone row edits reserve unlocked influence slots for the explicitly edited bones before choosing the strongest remaining donors. A selected bound bone with zero weight can therefore gain weight on the first small upward drag, even when the vertex already has four positive influences; no slider initialization is needed. The weakest unlocked donor is replaced when a slot is required, and the retained donors share the remaining weight in their previous proportions. Small row values remain exact when a donor slot is available.

Locked positive channels keep their values and slots. With three locked influences, introducing another bone assigns it the entire remaining unlocked weight because only one slot remains. Four locked influences prevent adding another influence. When selected positive influences exceed the remaining slots, the strongest edited influences survive. Weights stay normalized and use at most four positive channels. Auto, Smooth, Weld and Prune retain their existing distribution rules.

## Reversing a complete weight transfer

Manual row, Direct and brush adjustments keep a per-vertex copy of the last positive donor proportions for the same edited bone set. Raising bone_7 to 100% can make bone_10's active channel disappear; lowering bone_7 afterwards restores bone_10 from that copy instead of splitting the remainder among the first bound bones. Multiple donors return in their retained proportions, and separate vertices remember separate donors. Current positive donor weights always take priority over remembered values. Locks and the four-influence limit still apply, including exclusion of a donor previously evicted to make room for the edited influence.

The history is serialized only in the open Scene session, participates in row/stroke Undo/Redo, and does not add runtime influences, change the saved weight format or mark the mesh dirty by itself. A domain reload retains it; closing and reopening starts without history. Auto, Smooth, Weld, Prune, Swap and binding changes discard the manual history. If a newly opened vertex already has 100% on one bone, there is no earlier donor to infer; the existing equal-share fallback remains when no eligible remembered or active donor exists.

## Per-mesh triangle draw order

Unity's existing `SpriteMeshDataController.SortTrianglesByDepth` computes each vertex depth as the weighted sum of its bone depths, then sorts triangles by the mean of their three vertex depths. This governs triangles within a mesh; it does not replace SpriteRenderer sorting layers/order. Real PSB bone depths are shared across character meshes, so the Scene list uses private per-mesh ranks instead, as requested by the user.

Until the first explicit row reorder, the original triangle sequence remains intact. Afterwards `SceneWeightSession.DrawIndices()` applies the same weighted-depth calculation using list ranks. Sorting is stable for equal-depth triangles, preserves each triangle's vertex triplet and winding, and leaves source vertex positions and authored edges untouched. Preview uses this sequence immediately. Further weight edits invalidate the cached sequence, so layering follows the current weights. Undo also invalidates it. Bind appends new bones after saved ranks; Remove excludes missing bones from the effective list.

Ranks are saved by bone GUID in the selected sprite's `drawOrder` field in the namespaced importer metadata. Save writes the computed index sequence only for that sprite. Shared skeleton depths and other character layers remain unchanged. Reopening restores the row order. Other editor tools do not consume these custom ranks and may sort by real bone depths; reopening Edit Weights reapplies the local order in preview, and saving subsequent edits writes it back.

## Staging, preview and saving

The installed Unimator Editor DLL's scene manipulator registers a `duringSceneGui` Escape handler that clears `Selection.objects` and consumes the event. Edit Weights claims Escape in `beforeSceneGui` while its session is open, so that handler receives an already-used event and cannot clear Unity object selection. Both callbacks are unsubscribed on window disable; Unimator's DLL and shortcuts are left intact. Handling only the raw event in `duringSceneGui` proved insufficient in the user's interactive check.

`SceneWeightSession` owns a private `SceneBoneSession`/`SkinningCache` and serializes weights, bindings, draw ranks and selections independently of Sprite Editor preferences. Edits use cache Undo scopes and `meshChanged`; viewport strokes form a single undo operation. Geometry topology and positions are immutable; explicit draw ranks may reorder complete triangle triplets. Source-pose conversion is shared with Edit Bone; weights are not calculated using the captured posed skeleton.

The Scene host temporarily hides only the entry renderer using `forceRenderingOff` and draws a textured preview mesh with staged weights. It restores the original flag and Unity tool on closing, domain reload or blocking. The preview uses source texture alpha, so Overlay does not make transparent padding opaque. Existing SpriteSkin bind matrices deform the preview; newly bound character bones use the captured source-to-scene conversion until save regenerates bindings. Bone manipulation is left to Edit Bone.

Bone drawing and picking resolve current scene `SpriteSkin.boneTransforms` by GUID within the entry prefab/root and the same source asset, including sibling layer bindings. The entry renderer's bindings take priority. Positions, orientations and scaled lengths are read from live transforms for every Scene GUI pass, so Animation Window scrubbing moves both the visible bones and their hit areas. A bone without an active scene binding uses its captured cache segment as a Bind candidate. This lookup never writes the cached skeleton or source pose; Auto/Smooth/save semantics and session dirtiness are unaffected by animation sampling.

Preview calculations clear temporary Sprite Editor vertex overrides before deforming bind vertices. A missing selected Sprite or mismatched staged vertex/weight array lengths blocks interaction and restores the renderer/tool instead of indexing incomplete data. Reopen the host to reload this state.

Explicitly closing the popup, switching to another Scene editor or entering Play Mode automatically saves pending changes without confirmation; a failed controlled save keeps the tool open. Scene object selection changes restore the opening selection without prompting; Esc only clears the tool-local vertex selection and exits Bind; selected bones remain, and the host stays open. Saving changes the shared source Sprite/PSB or enabled UniskinRig, affecting every instance. Undo can revert staging before closing. External provider or importer-user-data changes reject a stale save. Edit Mesh, Edit Bone and Edit Weights save and close one another automatically. Opening Skinning Editor blocks Scene edits/saves for the same source. Native renderer/bone handles are suspended while the weight host is active.

`SkinningModule.ApplySceneWeightChanges` writes only the selected sprite's weight payload and, when explicit local draw ranks exist, its sorted triangle index sequence. It retains vertex positions and edges exactly; without local ranks it retains indices exactly as well. PSB binding changes update that layer's saved bone list and `CharacterPart.bones` in matching GUID order; the shared character skeleton and other layers remain intact. All edited vertices are limited to four positive normalized influences. Locked channels reserve their existing values and slots for row edits, painting, Auto and Prune; the Scene Smooth host reapplies that guarantee after the shared smoothing pass.

Ordinary Sprite providers lack a separate influence-list field. Their skeleton remains intact, and the Scene binding list is saved in a namespaced base64 JSON line, `Uniskin.WeightBindings.v1:`, in importer `userData`. The same per-sprite metadata also stores optional `drawOrder` GUIDs for both ordinary Sprites and PSB layers. Other user-data lines and other sprites' records are retained. On load, newly weighted bones from later Sprite Editor edits are also included, even if absent from the saved Scene binding list. Sprite Editor itself continues to display the ordinary Sprite's complete skeleton bone list.

Unbound character bones also resolve generated scene Transforms by their unique source hierarchy. This mapping is cached when the Scene host first draws, and positions/orientations are read live. Source CharacterData lengths are converted through `CharacterBoneLocalLength` using the source provider's PPU, matching the generated hierarchy even when texture resizing reduces runtime Sprite PPU. Runtime SpriteSkin lengths already include the texture definition scale and take priority. After changing this conversion, reopen an existing Scene session to rebuild previously captured poses; source skeleton data does not need to be recreated.

## Weld

The [Spine Weights guide](https://esotericsoftware.com/spine-weights#Weld) describes weight matching between meshes, requiring at least two common bound bones, with **All** and **Overlapping** options. Its documented user behavior does not specify the interpolation algorithm.

The [Spine developer's selection/lock clarification](https://ko.esotericsoftware.com/forum/d/26476-%EC%97%AC%EB%9F%AC-%EB%A9%94%EC%89%AC%EC%9D%98-%EA%B0%80%EC%A4%91%EC%B9%98%EB%A5%BC-%EB%8F%99%EC%8B%9C-%EC%A1%B0%EC%A0%88) confirms that Weld can be restricted to selected vertices and respects locked weights. The [different-topology clarification](https://ja.esotericsoftware.com/forum/d/26340-%E7%BD%91%E6%A0%BC%E6%9D%83%E9%87%8D%E7%BC%96%E8%BE%91) confirms that source and destination do not need equal vertex counts. Weld matches weights; it does not merge geometry or establish a persistent link between meshes.

In this fork, open **Edit Weights** on the destination mesh, click **Weld**, and choose a numbered source layer followed by **All** or **Overlapping**. Only other meshes within the same cached character asset with at least two common bound bone GUIDs are offered, including hidden layers. The current mesh is always the destination. No available source produces an explanatory disabled menu item. Single-sprite assets and transfers between different assets are unsupported. Numbered layer names distinguish duplicate names.

`SceneWeightSession.Weld` uses authored vertex positions transformed through each character part's matrix into common character coordinates. It clears temporary vertex-position overrides before sampling, so animation poses and Scene renderer transforms do not affect correspondence. `WeightWelding.Sample` interpolates source weight channels barycentrically within nondegenerate source triangles. **Overlapping** skips points outside every source triangle; boundary containment uses a dimensionless barycentric tolerance of `1e-5`. **All** also projects exterior points onto the nearest triangle edge and interpolates there. Coincident vertices reproduce their source weights; triangle winding and differing vertex counts are supported. This interpolation/projection algorithm is this fork's implementation choice, not a claim about Spine's unpublished algorithm.

Channels are matched by bone GUID, not influence-list order or bone name. Missing source bones are not automatically bound: their channels are omitted and the surviving unlocked common channels are normalized into the weight available after locked channels. Source points with no transferable positive weights, or with no transferable unlocked channels, leave the destination untouched. Locked positive channels retain their exact weights and reserve slots within Unity's four-influence limit; the strongest unlocked contributions fill the remaining slots. Bone-list selection does not restrict Weld's channels. Vertex selection restricts the destination set; with no selected vertices the whole destination is targeted.

One Weld action uses a cache Undo scope and raises `meshChanged`, invalidating the destination's computed draw order. Source weights, source bindings, destination geometry, bindings, and selections remain unchanged. Weights are staged until automatic saving on close or tool switch. Save persists only the destination sprite through the existing weight save path; Weld does not change shared skeleton data.

Regression coverage in `SceneWeightEditingTests` includes interpolation and reordered bone channels, All/Overlapping, degenerate triangles, missing mappings, invalid sources, and an optional multilayer PSB integration test for selection, locks, unchanged geometry/source, Undo/Redo and save/reload. The PSB test is skipped when no suitable rigged fixture exists.
