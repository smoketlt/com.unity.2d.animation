# Scene View Weight Editing

## Switching meshes without closing

Edit Weights shares the [Scene mesh switching workflow](SceneMeshEditing.md#switching-meshes-without-closing). Click another visible authored mesh in the same rig in Scene View or select its GameObject alone in Hierarchy; if vertices are selected, the first click only clears them and the next click switches. A target without authored geometry is silently ignored without a Create Mesh dialog, saving or preview cleanup. Bone hits, modifier gestures, Bind and Weld picking retain their existing input.

In Edit Weights, Scene mesh clicks commit on primary mouse release within 3 GUI points of the press, with no drag events or modifiers. Any drag permanently cancels that click, even when returning to the press position. Add/Remove defer their first stamp over a potential mesh target until dragging begins, then paint the original mesh from the press position with the normal spacing and Undo scope. A target-selection click never paints. Direct retains the vertex selection until release or rectangle dragging, so its first target click still only clears vertices. Lost input cancels target selection; Escape and gesture cleanup discard both the pending target and stamp. Hierarchy switching remains immediate.

The outgoing session finishes its gesture and saves weights before restoring temporary Preview Pose changes and destroying its sorted preview. The old renderer's prior forceRenderingOff value is restored. Preview Pose resets the touched bones using the existing saved reference/animation-channel cleanup, then all pose tracking, bone lookup, vertex/bone selection, locks and donor history are discarded with the old session. The new session captures the cleaned scene pose. Brush/display preferences remain window preferences; Preview Pose and Weld do not carry over. The same popup remains open and selects the new renderer in Unity. Save or validation failure prevents the target change. See the linked page for verification and remaining interactive checks.

## Entry and scope

For an enabled [UniskinRig](UniskinRig.md), Save persists weights, bindings and draw ranks in the rig and updates its generated Sprite subassets without PSB reimport. The native importer workflow described below applies when no rig is enabled; Bake transfers the same provider payload to PSB.

The SpriteRenderer Inspector exposes **Edit Weights** below Edit Mesh and Edit Bone when the Sprite has authored importer geometry. This button opens the floating UI Toolkit popup; there is no Window menu entry. The popup pins Unity selection to the current editing renderer. Explicit same-rig Scene or Hierarchy mesh switching updates that target and its pinned selection without closing. Empty Scene clicks and unrelated or multiple Hierarchy selection restore the current pinned selection on the next editor update; they never request closing or display a save prompt. Merely selecting an object does not activate the host.

The window follows Edit Mesh/Bone's dark styling, draggable title and red close button. Drag its bottom edge grip to resize height; the scrollable bone list fills the available space. Supplied `Weights.png`, `Smooth.png`, `Bind.png`, `Auto.png`, `Prune.png`, `Swap.png`, `Weld.png`, `UpdateBind.png` and `Delete.png` are used; Delete is assigned to Remove. Influence is absent. **Update Bindings** is a full-width, 30-pixel-high button below the Bind/Swap/Remove row.

Position, size, chosen mode, Strength/Size/Feather/Step and Pieces/Overlay/Selected/Triangles/Preview are saved in per-project EditorPrefs under `Unity.2D.Animation.SceneEditWeights.<Application.dataPath>`. New openings restore them. Domain reload closes the popup; reopening restores these preferences. Saving preferences runs on control changes, on close and periodically while open to capture dragging/resizing, and only writes when values change. Bind, gestures, bone/vertex selections and bone locks are session state and are not carried to another mesh. Corrupt/non-finite preferences are ignored and slider values are clamped to their ranges.

Rows, sliders, viewport bones, pieces and overlay share `BoneColorUtility.GetWeightMapColor`, the fixed Skinning Editor weight palette. Row slider fills match their bone, use the numeric field's height and hide the dragger/end marker. Locked swatches use the same embedded lock texture as `WeightInspector`, rather than a text glyph. Bone-name pointer handling runs in the trickle-down phase so the built-in Button manipulator cannot consume plain clicks before selection.

Rows have a fixed, non-shrinking height. Swatches are 20 by 20 physical pixels, inset 4 pixels from the dark list edge; bone names start 4 pixels after the swatch and use left text alignment with no internal horizontal padding. Name-column widths follow the Swap button's left world-coordinate, keeping every bone track aligned to that edge after layout/resizing. Slider input, drag container, tracker and numeric field heights are pinned inline to 20 physical pixels (scaled by pixelsPerPoint), including minimum/maximum height and zero vertical margins/padding. This overrides Unity's more specific horizontal-slider rules that kept the visible track near 13 pixels despite the earlier USS changes. Slider drag containers stretch across their available width. Do not center the drag container with `align-self: center`: its content is positioned absolutely, so its intrinsic width can collapse and hide both the tracker and fill while leaving the numeric field visible. Tracker top/bottom offsets and margins are explicitly aligned to the container; the default thin-slider centering offset must not remain on a full-height fill, because that makes it overlap the next row after resizing.

## Commands and input

### Selected vertex weight clipboard

The **Copy** and **Paste** icon buttons below Smooth/Auto/Weld transfer complete vertex weight distributions. Select vertices with Ctrl/Cmd+click or a rectangle, then Copy. One copied vertex can be pasted to any nonempty selection. Multiple copied vertices require an equal target count and map pairwise in selection order. Click selection retains chronological order, including deselect/reselect (the reselected vertex goes last). Rectangle selection appends vertices in mesh index order. The shared selection HashSet is not used as the ordering contract.

The clipboard is an in-memory snapshot shared between Edit Weights sessions, allowing transfers between meshes until a domain reload. Bone GUIDs, rather than palette rows, names or local indices, identify influences. A target vertex is skipped entirely if any positive source influence is absent from its mesh's bound bones; other pairs still paste, without shifting their mapping. A conflicting locked channel also skips the entire target vertex. Compatible distributions are copied exactly, including cleared weights. No selection never means the whole mesh. Copy/Paste are disabled during Bind and Preview Pose; Paste also requires a populated clipboard and compatible counts. Changes are staged, emit `meshChanged` and support one-step Undo; Save persists them through the existing workflow.

During **Bind**, selecting bone GameObjects in the Hierarchy adds matching unbound bones to this mesh before restoring the popup's pinned object selection. Multi-selection is supported. ## Preview Pose and Reset Pose

The **Triangles** checkbox also applies during Preview Pose: when enabled, triangle edges follow the current deformed mesh, independently of Scene Gizmos and the Preview checkbox. Their color is configured under **Preferences > Uniskin > Mesh Editing > Weight Triangle Color**, defaults to opaque yellow, and uses 2-point lines for visibility. Changes repaint immediately and persist in user EditorPrefs; Reset Mesh Editing Defaults restores yellow. When disabled, Preview Pose shows no mesh lines. Authored-edge colors, vertex handles and weight overlays remain hidden in this mode.

A separator below **Update Bindings** introduces **Preview Pose** and **Reset Pose**, using `PreviewPose.png` and `ResetPose.png`. Preview Pose is a session mode, separate from the persisted Preview display checkbox. It renders the staged sprite without weight overlays and keeps Scene bones visible when Gizmos is enabled. Select bound bones in the viewport or popup rows. With **W / Move**, use the existing `SkeletonView` `EditPose` gestures: drag a joint to translate the selected bones and drag a bone body to rotate around its selected root. No object position gizmo replaces these bone gestures. **E** and **R** retain explicit rotation and scale handles. Multiple selected bones transform together; selected descendants inherit their selected ancestor's change once. Alt and the View tool retain Scene navigation.

Reset targets come from the saved binding reference, never from the current scene pose on window/preview entry. Resolve each bone's world reference from this mesh's GUID-keyed Update Bindings matrices, otherwise from its Sprite bind pose, with source-skeleton fallback for other resolved bones; convert to local TRS using the parent's reference matrix. Refresh these targets after Update Bindings. Leaving Preview Pose re-enables weight editing and retains its pose while this popup stays open. **Reset Pose** is available inside or outside Preview Pose, including before the first preview entry. Closing Edit Weights (also switching to Edit Mesh/Bones or domain reload) restores touched preview bones to their binding reference. Reopening therefore cannot promote a preview pose to a new default. Preview writes do not explicitly create prefab overrides and do not change source skeleton data, weights, topology or binding matrices, or dirty staged weights.

Track the last preview-written local TRS and the latest external animation sample separately, component by component. Reset/close preserves animated position, rotation or scale channels at their latest sampled frame while removing temporary changes from other channels. Unity AnimationMode property flags cover channels already animated before the first preview edit; subsequent external sampling is also detected, including non-AnimationMode clip samplers. Stopping Unity AnimationMode clears the sampled-channel flags so binding reset becomes available again. Playback may overwrite a manual preview gesture on its next sample; the popup does not pause playback or modify clips. Ordinary preview transformations/reset use scene Transform Undo; inside Unity AnimationMode they avoid Transform Undo recording, preventing automatic animation key recording. Cleanup runs before weight auto-save and unsubscribes animation tracking with the popup lifecycle.

While Preview Pose is active, Scene weight gestures, row sliders, locks/reordering, weight steps, Prune, Smooth, Auto, Weld, Bind, Swap, Remove and Update Bindings are blocked. Starting Preview Pose finishes Bind and cancels active weight gestures and Weld picking. The button remains highlighted until toggled off; Reset Pose does not exit the mode. The existing Preview checkbox retains its previous preference and behavior when pose mode ends. Source weight saves remain independent of these scene pose edits.

## Scene preview color and transparency

With Preview off, the textured mesh draws in Scene View's handles layer. Unity composites that layer without the final sRGB conversion used for the scene image; see the [Unity 6000.0 SceneView source](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.0/Editor/Mono/SceneView/SceneView.cs#L2458). Preview uses the native scene renderer described below, so the scene pipeline supplies its normal color conversion. The Handles texture draw is used only with Preview off and leaves `_AdjustLinearForGamma` disabled, retaining Dim. With Preview off, all editing modes retain the previous Dim appearance. Palette colors are already display colors. Gamma projects leave this correction off. Toggling Preview off restores Dim together with the configured editing visuals. Opening Edit Weights alone does not remove Dim.

`SceneWeightsPreview.shader` outputs premultiplied RGB with `Blend One OneMinusSrcAlpha`, matching the Scene GUI compositor. Source texture alpha and SpriteRenderer alpha control coverage once. This also preserves partially transparent texels rather than squaring their alpha in the intermediate handles target. Preview still controls drawing only; all editing gestures remain available.

## Introducing an influence at the four-weight limit

Direct drags, Add brush stamps and bone row edits reserve unlocked influence slots for the explicitly edited bones before choosing the strongest remaining donors. A selected bound bone with zero weight can therefore gain weight on the first small upward drag, even when the vertex already has four positive influences; no slider initialization is needed. The weakest unlocked donor is replaced when a slot is required, and the retained donors share the remaining weight in their previous proportions. Small row values remain exact when a donor slot is available.

Locked positive channels keep their values and slots. With three locked influences, introducing another bone assigns it the entire remaining unlocked weight because only one slot remains. Four locked influences prevent adding another influence. When selected positive influences exceed the remaining slots, the strongest edited influences survive. Weights stay normalized and use at most four positive channels. Auto, Smooth, Weld and Prune retain their existing distribution rules.

## Reversing a complete weight transfer

Manual row, Direct and brush adjustments keep a per-vertex copy of the last positive donor proportions for the same edited bone set. Raising bone_7 to 100% can make bone_10's active channel disappear; lowering bone_7 afterwards restores bone_10 from that copy instead of splitting the remainder among the first bound bones. Multiple donors return in their retained proportions, and separate vertices remember separate donors. Current positive donor weights always take priority over remembered values. Locks and the four-influence limit still apply, including exclusion of a donor previously evicted to make room for the edited influence.

The history is serialized only in the open Scene session, participates in row/stroke Undo/Redo, and does not add runtime influences, change the saved weight format or mark the mesh dirty by itself. Closing, including closure before domain reload, ends this history; reopening starts without it. Auto, Smooth, Weld, Prune, Swap and binding changes discard the manual history. If a newly opened vertex already has 100% on one bone, there is no earlier donor to infer; the existing equal-share fallback remains when no eligible remembered or active donor exists.

## Per-mesh triangle draw order

Unity's existing `SpriteMeshDataController.SortTrianglesByDepth` computes each vertex depth as the weighted sum of its bone depths, then sorts triangles by the mean of their three vertex depths. This governs triangles within a mesh; it does not replace SpriteRenderer sorting layers/order. Real PSB bone depths are shared across character meshes, so the Scene list uses private per-mesh ranks instead, as requested by the user.

Until the first explicit row reorder, the original triangle sequence remains intact. Afterwards `SceneWeightSession.DrawIndices()` applies the same weighted-depth calculation using list ranks. Sorting is stable for equal-depth triangles, preserves each triangle's vertex triplet and winding, and leaves source vertex positions and authored edges untouched. Preview uses this sequence immediately. Further weight edits invalidate the cached sequence, so layering follows the current weights. Undo also invalidates it. Bind appends new bones after saved ranks; Remove excludes missing bones from the effective list.

Ranks are saved by bone GUID in the selected sprite's `drawOrder` field in the namespaced importer metadata. Save writes the computed index sequence only for that sprite. Shared skeleton depths and other character layers remain unchanged. Reopening restores the row order. Other editor tools do not consume these custom ranks and may sort by real bone depths; reopening Edit Weights reapplies the local order in preview, and saving subsequent edits writes it back.

## Staging, preview and saving

The popup always closes before domain reload without saving, with Scene/selection/tool cleanup. Restored startup/reload windows close on the next editor delay callback without reconstructing a session or registering Scene handlers. See [Domain reload and restored windows](SceneMeshEditing.md#domain-reload-and-restored-windows) for the shared lifecycle and regression checks.

The installed Unimator Editor DLL's scene manipulator registers a `duringSceneGui` Escape handler that clears `Selection.objects` and consumes the event. Edit Weights claims Escape in `beforeSceneGui` while its session is open, so that handler receives an already-used event and cannot clear Unity object selection. Both callbacks are unsubscribed on window disable; Unimator's DLL and shortcuts are left intact. Handling only the raw event in `duringSceneGui` proved insufficient in the user's interactive check.

`SceneWeightSession` owns a private `SceneBoneSession`/`SkinningCache` and serializes weights, bindings, draw ranks and selections independently of Sprite Editor preferences. Edits use cache Undo scopes and `meshChanged`; viewport strokes form a single undo operation. Weight commands retain geometry positions and topology; Update Bindings explicitly replaces bind-space positions. Explicit draw ranks may reorder complete triangle triplets. Source-pose conversion is shared with Edit Bone; weights are not calculated using the captured posed skeleton.

The Scene host temporarily hides only the entry renderer using `forceRenderingOff` and draws a textured preview mesh with staged weights. It restores the original flag and Unity tool on closing, domain reload or blocking. The preview uses source texture alpha, so Overlay does not make transparent padding opaque. Existing SpriteSkin bind matrices deform the preview; newly bound character bones use the captured source-to-scene conversion until save regenerates bindings. Bone manipulation is left to Edit Bone.

Undo/Redo of staged weights must retain every character layer's texture coordinates, including after closing the window. The enabled UniskinRig rebuild path explicitly restores generated Sprite UVs from the original imported Sprite; cleared native UV streams previously made sibling layers disappear while only the selected layer's independent preview remained. See [UniskinRig](UniskinRig.md#conflicts-and-undo) for the derived-data repair and atlas mapping.

Bone drawing and picking resolve current scene `SpriteSkin.boneTransforms` (including disabled components) by GUID within the entry prefab/root and the same source asset, including sibling layer bindings. The entry renderer's bindings take priority. Positions, orientations and scaled lengths are read from live transforms for every Scene GUI pass, so Animation Window scrubbing moves both the visible bones and their hit areas. A bone without an active scene binding uses its captured cache segment as a Bind candidate. This lookup never writes the cached skeleton or source pose; Auto/Smooth/save semantics and session dirtiness are unaffected by animation sampling.

Preview calculations clear temporary Sprite Editor vertex overrides before deforming bind vertices. A missing selected Sprite or mismatched staged vertex/weight array lengths blocks interaction and restores the renderer/tool instead of indexing incomplete data. Reopen the host to reload this state.

Explicitly closing the popup, switching to another Scene editor or entering Play Mode automatically saves pending changes without confirmation; a failed controlled save keeps the tool open. Scene object selection changes restore the opening selection without prompting; Esc only clears the tool-local vertex selection and exits Bind; selected bones remain, and the host stays open. Saving changes the shared source Sprite/PSB or enabled UniskinRig, affecting every instance. Undo can revert staging before closing. External provider or importer-user-data changes reject a stale save. Edit Mesh, Edit Bone and Edit Weights save and close one another automatically. Opening Skinning Editor blocks Scene edits/saves for the same source. Native renderer/bone handles are suspended while the weight host is active.

`SkinningModule.ApplySceneWeightChanges` writes the selected sprite's weight payload and, when explicit local draw ranks exist, its sorted triangle index sequence. Positions are written when the session has a custom binding pose; ordinary weight saves retain positions exactly. Edges remain unchanged; without local ranks indices remain unchanged as well. PSB binding changes update that layer's saved bone list and `CharacterPart.bones` in matching GUID order; the shared character skeleton and other layers remain intact. All edited vertices are limited to four positive normalized influences. Locked channels reserve their existing values and slots for row edits, painting, Auto and Prune; the Scene Smooth host reapplies that guarantee after the shared smoothing pass.

## Update Bindings

This follows [Spine Update bindings](https://esotericsoftware.com/spine-weights#Update-bindings): the current displayed vertices and live bone transforms become the mesh's new reference. The command uses all bound bones and all vertices, including bones currently carrying zero weight. Changing normalized weights in that same pose therefore does not move vertices. Subsequent bone motion deforms the mesh from the new reference; existing animation frames can look different after rebinding. Bone Transforms, animation clips and the shared source skeleton are not rewritten. Other meshes retain their own binding poses; other instances of this same Sprite use the saved reference.

`SceneMeshBindingPose` stores GUID-keyed pixel-to-bone matrices normalized by authoring PPU, reference vertices, their original texture positions and mapping triangles in a separate per-Sprite `Uniskin.MeshBindingPose.v1:` importer metadata line. UniskinRig retains the same line in its detached document and transfers it during Bake. Runtime matrices are derived from the current Sprite rect/pivot/PPU, so renderer/root transforms and texture downsampling are not baked into world coordinates. SpriteRenderer flips are applied after skinning in the viewport and are not baked into the reference.

Save, ordinary import, cached Uniskin PSB import, rig Sprite rebuild and missing-UV repair restore the custom bind matrices and texture mapping. Repeated Update operations compose the texture mapping rather than resampling the image. Later Scene Edit Mesh vertex changes use the saved triangle mapping for interpolation/extrapolation; the source image and topology are not regenerated by Update. Staged data participates in Undo while open; domain reload discards it and closes the popup. An explicit serialized presence flag prevents Unity's inline-object serialization from treating an undone absent binding as a default empty binding object.

Auto uses the mesh-specific reference established by Update Bindings. The inverse of each saved pixels-to-bone matrix maps the bone-local origin and local-length endpoint, in provider pixel units, into the same reference space as the mesh vertices. This handles bone rotation, translation and scale without sampling the current animation frame. Zero-length bones remain point handles. Without a custom reference, Auto retains the original source-pose generation. Smooth retains its existing mesh-neighborhood rules. Update Bindings does not change the shared skeleton's default pose or SpriteSkin's Reset Bind Pose behavior.

Auto resolves and calculates the generated distribution before changing staged weights or manual donor history. A missing or invalid reference for any participating bone rejects the operation and requests Update Bindings; source-space bones must never be mixed with rebound vertices. This can occur after adding bindings to a mesh that already has a custom reference. Applying the distribution remains one Undo operation, preserves locked channels and unselected vertices, and emits meshChanged once. Geometry, texture coordinates, topology and saved binding matrices are unchanged. BBW quality still depends on mesh topology and the placement of its bone handles; a correct reference does not guarantee an artist's intended distribution for every mesh.

Scene Auto uses `RefinedBiharmonicWeightsGenerator` to prepare a temporary conforming solver mesh. Up to three uniform midpoint passes refine its triangle surface, with shared-edge midpoints and conservative 8,192-vertex/triangle budgets for refinement. Original vertices remain a prefix of the solver vertices, so BBW returns weights directly for the authored vertices without nearest-vertex transfer. Control samples and bone endpoints replace their parent triangles; points on an edge split both adjacent triangles, and existing vertices are reused. Unreferenced authored vertices are inserted if they lie on the surface. Samples outside the surface do not extend the authored domain. The temporary refinement never changes saved geometry or texture mapping. Native BBW errors or empty vertex solutions reject Auto before applying weights instead of silently assigning failed vertices to the first bone.

This addresses a second, independent defect in the upstream generator's preparation: it appends three triangles for a control sample while retaining their overlapping parent. Sparse, uneven cages additionally produce poor BBW discretization even when their vertex arrangement is symmetric. The Scene-specific preparation replaces this path; Sprite Editor generation and its scheduled job keep their existing generator. No weight mirroring or one-side copying is imposed, so asymmetric rigs retain their intended influences.

## Weld

For a Clipping Mask destination, source meshes come from its owning rig's separate character document, including the body layer with the same Sprite ID. The contour-to-character pixel conversion accounts for its authoring plane, PPU and rig root offset. Only the contour receives saved weight changes; the source mesh and rig are unchanged. See [Masking: Weld from character meshes](Masking.md#weld-from-character-meshes).

The [Spine Weights guide](https://esotericsoftware.com/spine-weights#Weld) describes weight matching between meshes, requiring at least two common bound bones, with **All** and **Overlapping** options. Its documented user behavior does not specify the interpolation algorithm.

The [Spine developer's selection/lock clarification](https://ko.esotericsoftware.com/forum/d/26476-%EC%97%AC%EB%9F%AC-%EB%A9%94%EC%89%AC%EC%9D%98-%EA%B0%80%EC%A4%91%EC%B9%98%EB%A5%BC-%EB%8F%99%EC%8B%9C-%EC%A1%B0%EC%A0%88) confirms that Weld can be restricted to selected vertices and respects locked weights. The [different-topology clarification](https://ja.esotericsoftware.com/forum/d/26340-%E7%BD%91%E6%A0%BC%E6%9D%83%E9%87%8D%E7%BC%96%E8%BE%91) confirms that source and destination do not need equal vertex counts. Weld matches weights; it does not merge geometry or establish a persistent link between meshes.

In this fork, open **Edit Weights** on the destination mesh and click **Weld**. Its button pulses with the same two-second highlight as Bind while waiting for a primary Scene View click on the source SpriteRenderer. Picking keeps the destination and Unity object selection fixed and suspends weight-painting, bone picking and vertex selection. The clicked renderer must be another eligible mesh in the same character instance/root and source asset, with at least two common bound bone GUIDs. Invalid or empty clicks keep picking active and show a status hint. A valid click stops the pulse and opens only **All** / **Overlapping**, with the source name displayed above them; dismissing that menu changes no weights. Esc or another Weld click cancels picking without clearing selected vertices or bones. Starting Weld completes active Bind; other weight commands cancel pending Weld picking. Blocking or closing the host also ends picking; it is not persisted. No eligible source produces an explanatory message. Hidden objects must be made pickable in the Scene View first. Single-sprite assets and transfers between different assets are unsupported.

`SceneWeightSession.Weld` uses authored vertex positions transformed through each character part's matrix into common character coordinates. It clears temporary vertex-position overrides before sampling, so animation poses and Scene renderer transforms do not affect correspondence. `WeightWelding.Sample` interpolates source weight channels barycentrically within nondegenerate source triangles. **Overlapping** skips points outside every source triangle; boundary containment uses a dimensionless barycentric tolerance of `1e-5`. **All** also projects exterior points onto the nearest triangle edge and interpolates there. Coincident vertices reproduce their source weights; triangle winding and differing vertex counts are supported. This interpolation/projection algorithm is this fork's implementation choice, not a claim about Spine's unpublished algorithm.

Channels are matched by bone GUID, not influence-list order or bone name. Missing source bones are not automatically bound: their channels are omitted and the surviving unlocked common channels are normalized into the weight available after locked channels. Source points with no transferable positive weights, or with no transferable unlocked channels, leave the destination untouched. Locked positive channels retain their exact weights and reserve slots within Unity's four-influence limit; the strongest unlocked contributions fill the remaining slots. Bone-list selection does not restrict Weld's channels. Vertex selection restricts the destination set; with no selected vertices the whole destination is targeted.

One Weld action uses a cache Undo scope and raises `meshChanged`, invalidating the destination's computed draw order. Source weights, source bindings, destination geometry, bindings, and selections remain unchanged. Weights are staged until automatic saving on close or tool switch. Save persists only the destination sprite through the existing weight save path; Weld does not change shared skeleton data.

Regression coverage in `SceneWeightEditingTests` includes interpolation and reordered bone channels, All/Overlapping, degenerate triangles, missing mappings, invalid sources, and an optional multilayer PSB integration test for selection, locks, unchanged geometry/source, Undo/Redo and save/reload. The PSB test is skipped when no suitable rigged fixture exists.
